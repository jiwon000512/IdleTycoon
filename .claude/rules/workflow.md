# 작업 절차

늘 읽힌다. 모든 작업에 적용한다.

## 묻기

- 기획·규칙을 바꾸는 결정은 객관식으로 묻고 권장안을 표시한다. 확정되면 기획서 아티팩트 「확정 결정」 표와 변경 이력에 반영한다.
- 질문은 질문으로 답한다. 「~할 수 있나」를 변경 요청으로 읽지 않고, 가능 여부와 결과부터 답한다.
- 구현 중에는 사용자를 기다리지 않는다. 기본값으로 진행하고 보고에 적는다.

## 절차

1. **설계**: 새 기능·구조 변경만. 아티팩트에 코드 설계와 검증 항목을 적어 확인받는다. 값·위치·문구 같은 작은 수정은 바로 한다.
2. **구현**: 한 번에 전부(스크립트·프리팹·데이터·더미 리소스).
3. **검증**: 컴파일 0 · 콘솔 0 · EditMode 테스트 · 플레이에서 확인(캡처 또는 상태 값). 검증 중 발견한 버그는 그 자리에서 고친다.
4. **보고**: 만든 것 · 검증 결과 · 설계와 달라진 점. 확인하지 못한 것은 못 했다고 적는다.

- 사용자가 작업을 요청했으면 에디터가 플레이 중이어도 끄고 진행한다.
- 새 리소스(그림·소리)는 시안 3개 → 비교 페이지 → 사용자 선택 → 적용 1회. 한 번에 하나씩.
- 기획서의 숫자는 코드에 쓰지 않고 JSON 테이블에 둔다.
- 기획 회차는 같은 주제로 2회를 넘기지 않는다. 그 뒤에는 실제 코드 안에서 수직 슬라이스로 만들어 플레이로 판정한다.

## 커밋

- 완료 직후에는 커밋하지 않는다(사용자가 플레이해 보는 시간). 사용자가 **다음 작업을 언급하거나 「커밋」이라고 하면** 검증이 끝난 앞 작업을 묻지 않고 커밋 + `origin main` 푸시한다.
- 규칙·문서 개정은 기능과 커밋을 나눈다. GameKit(`C:\project\UnityGameKit`) 변경은 그 저장소에 따로 커밋한다.
- 메시지는 한국어 한 줄 요약 + 필요하면 본문.

## 아티팩트

- 설명·비교·설계·보고는 아티팩트로 한다.
- 다음 작업으로 넘어가면 앞 작업의 아티팩트를 묻지 않고 삭제하고 문서의 링크도 지운다. 남기는 것은 기획서 「사업가 웜뱃」과 루프 기획 회차(1~7회차) 아티팩트다. 사용자가 남기라고 한 것은 지우지 않는다. 결정은 기획서와 진행상황에 글로 남긴다.
- 아티팩트를 지우면 그 주소가 열린 크롬 탭도 닫는다(browser-use `list_tabs`).

## 문서

- 기능이 끝나면 `기획/진행상황.md`와 `기획/포트폴리오.md`(4장에 한 절, 5장 숫자)를 고친다.
- **늘 읽히는 문서**(`CLAUDE.md`, 이 파일, `진행상황.md`)는 합쳐 12KB 안으로 둔다. `진행상황.md`는 한 항목 200자 안, 끝난 기능의 구현 세부는 적지 않는다(코드·포트폴리오·git에 있다).
- 새 규칙은 해당 `.claude/rules/` 파일에 한 줄로 넣는다. 같은 규칙을 두 곳에 쓰지 않는다. 폐기된 규칙은 지운다(이력은 git).
- 절차·요령·도구 함정은 `.claude/skills/`에 둔다. 에이전트 메모리에는 저장소에 없는 것(사용자 취향·외부 위치)만 둔다.
