# 데이터 테이블 규칙

버전 v1.38 · 2026-09-26
게임 데이터(빵·업그레이드·손님 외형·문구·수식 상수)를 JSON 파일로 관리하는 규칙. 사람과 AI 에이전트가 이 문서를 보고 JSON을 만들고 고친다. 기획서(`동물원-타이쿤-기획서.md`)의 표가 "무엇을 넣을지"를 정하고, 이 문서는 "어떤 형태로 넣을지"를 정한다.

---

## 1. 결정 (2026-09-13)

| 항목 | 결정 |
|---|---|
| 원본 | JSON 파일이 유일한 원본. ScriptableObject는 쓰지 않는다 |
| 이름 | 파일 이름 = `table` 값 = 행 클래스 이름 = `XXTable`(PascalCase, `BreadTable.json` ↔ `BreadTable.cs`). 행 클래스는 한 행이고 칸을 자료형(숫자·enum·목록)으로 가진다 (v1.34) |
| 로드 | GameKit `TableSet`이 테이블을 처음 부를 때 `Resources.Load<TextAsset>("Data/XXTable")`로 읽어 Newtonsoft.Json으로 행 클래스에 역직렬화한다. 문자열 enum 칸은 enum으로 읽는다 (v1.34) |
| 조회 | 모든 행 클래스는 GameKit `Table<TId>`(Id는 string 또는 int)를 상속하고, 조회는 `Get<T>(id)`·`GetAll<T>()`(파일 행 순서) 두 가지뿐이다. 하나뿐인 값 묶음도 Id로 찾는 행 테이블이다(예외 없음, v1.34) |
| 파서 | Newtonsoft.Json (`com.unity.nuget.newtonsoft-json`) |
| 파일 구성 | 테이블당 파일 1개 |
| 에셋 참조 | JSON의 경로 칼럼(`Resources/` 기준)으로 `Resources.Load`. 더미 리소스를 먼저 두고 실제 리소스로 교체 (2026-09-14 변경) |
| 검증 | EditMode 테스트가 모든 테이블을 로드해 규칙(7장)을 검사한다. 테스트 실패 = 데이터 오류 |
| UI 문구 | 화면에 보이는 모든 문자열은 `StringTable.json`에서 온다. 코드·프리팹에 한국어 리터럴을 두지 않는다 (2026-09-14) |

## 2. 위치와 파일

```
ProjectTycoon/Assets/Resources/
├─ Data/
│  ├─ ConfigTable.json         게임 전체에 하나뿐인 값: 시작 코인·굴 칸·걷기 속도·드는 빵 수 (8.4)
│  ├─ BakeryConfigTable.json   빵집 시뮬 숫자 (8.4)
│  ├─ PlazaConfigTable.json    굴 밖 광장 숫자 (8.4)
│  ├─ PlazaDecorTable.json     광장에 놓인 장식 (8.14)
│  ├─ VisitorTable.json        손님 외형 (8.5)
│  ├─ BreadTable.json          빵 (8.8)
│  ├─ ActionTable.json         웜뱃 행동 종류·수동/자동 (8.10)
│  ├─ InteractableTable.json   웜뱃이 다루는 사물·거리·행동·업그레이드 (8.11)
│  ├─ SoundTable.json          효과음 (8.12)
│  ├─ DecorationTable.json     광장 장식 종류 (8.13)
│  └─ StringTable.json         UI 문구 (8.7)
├─ Audio/<소리 id>.wav      효과음 (SoundTable.clip)
└─ Sprites/
   ├─ Shop/Breads/*.png      빵 아이콘 (BreadTable.sprite)
   ├─ Actions/<행동 id>.png  상호작용 버튼 아이콘 (ActionTable.icon. 임포트 규칙 5장)
   ├─ Decor/<장식 id>.png    광장 장식 (DecorationTable.sprite. 임포트 규칙 5장)
   └─ Visitors/<종>/*.png    손님 아트 (VisitorTable.sprite·시트 경로 칼럼. 임포트 규칙 5장)
```

`game_config.json`은 v1.34에서 설정 테이블 4개로 나눴다(8.4). `grades.json`·`facilities.json`은 2026-09-18 「사업가 웜뱃」 전환으로 뽑기·시설과 함께 삭제했다(v1.12). `animals.json`은 v1.14, `zoo_levels.json`은 v1.23(설계 09, 지상 폐기)에서 삭제.

- 파일 이름은 행 클래스 이름 + `.json`(`XXTable.json`, v1.34 전에는 `snake_case.json`). 새 테이블을 추가하면 이 표와 8장 스키마에 함께 적고, Core `Scripts/Core/Tables/`에 같은 이름의 행 클래스를 만든다.
- 런타임 저장 데이터(세이브 파일)는 테이블이 아니다. 여기 규칙을 따르지 않고 `Application.persistentDataPath`에 따로 둔다.

## 3. 공통 구조

행(row)이 여러 개인 테이블:

```json
{
  "table": "BreadTable",
  "version": 2,
  "notes": ["사람/에이전트를 위한 메모. 로더는 무시한다."],
  "rows": [ { ... }, { ... } ]
}
```

모든 테이블이 `rows`를 가진다. 하나뿐인 값 묶음도 행으로 적고 `id`로 찾는다(8.4, v1.34).

| 필드 | 규칙 |
|---|---|
| `table` | 파일 이름(확장자 제외) = 행 클래스 이름과 같아야 한다. 다르면 `TableSet`이 읽을 때 예외 |
| `version` | 정수. **스키마(필드 구조)가 바뀔 때만** +1. 값만 바꿀 때는 올리지 않는다. 로더는 지원하지 않는 version이면 오류 |
| `notes` | 문자열 배열. 선택. 미결 항목·출처·주의점을 적는다. JSON은 주석이 없으므로 주석 대용 |
| `rows` | 행 배열. 순서는 `sortOrder`가 따로 있으면 무시되고, 없으면 파일 순서가 표시 순서. 모든 행은 `id`(string 또는 int)를 가지며 비었거나 겹치면 `TableSet`이 읽을 때 예외 |

## 4. 표기 규칙

- **키**: `camelCase`. 영어만. 축약하지 않는다 (`baseIncomePerSecond`, `incPerSec` ✗).
- **ID**: 문자열, `^[a-z][a-z0-9_]*$`(놓인 자리 번호 같은 순번은 int, v1.34). 설정 값 이름(`ConfigTable`의 `startCoins` 등)은 키와 같은 camelCase.
- **enum 칸**: 소문자 문자열(`"manual"`, `"head"`)로 적고 행 클래스의 enum(`ActionMode.Manual`)으로 대소문자 무관하게 읽는다. 모르는 값이면 읽을 때 예외(v1.34, 검증기가 문자열을 검사하지 않는다). 동물 ID는 `a` + 두 자리 번호(`a01`~`a99`). 번호는 재사용하지 않는다(삭제된 종의 번호는 비워 둔다).
- **표시 이름**: `name`에 한국어. 다국어를 도입하면 `nameKey`로 바꾸고 `name`을 지운다(version +1).
- **숫자**: 배수·비율은 소수(`0.5` = +50%), 퍼센트 정수를 쓰지 않는다. 확률은 **가중치**(정수)로 적고 로더가 합으로 나눈다. 시간은 초 단위 정수. 코인은 정수(내부 계산은 double).
- **불리언**: `true/false`. 0/1을 쓰지 않는다.
- **없음**: `null`. 필드를 생략하지 않는다 — 모든 행은 같은 필드 집합을 가진다(누락 검출을 위해).
- **색**: `"#RRGGBB"` 문자열.
- 들여쓰기 2칸, UTF-8, LF, 파일 끝 개행.

## 5. 에셋 참조 규칙 (2026-09-14 변경)

에셋은 JSON의 **경로 칼럼**으로 가리킨다. 값은 `Resources/` 아래 상대 경로(확장자 없음)이며 코드가 `Resources.Load(path)`로 읽는다. 이름을 바꾸거나 다른 파일로 바꿀 때 JSON 값만 고치면 된다.

| 에셋 | 칼럼 | 값 예 | 없을 때 |
|---|---|---|---|
| 동물 정지 그림·시트 | `animals.sprite`, `idleSheet`, `moveSheet` | `Sprites/Animals/Wombat/Wombat_Idle` | 검증 실패(테스트) |
| UI 프리팹 | 칼럼 없음. GameKit `UIManager`가 `UI/{뷰 타입 이름}` 규칙으로 로드 | `Resources/UI/TopBarView` | — |

- 개발 중에는 에이전트가 경로 자리에 **더미 리소스**(단색 스프라이트 등)를 만들어 둔다. 사용자가 같은 경로·이름의 실제 리소스로 덮어써 교체한다. 교체 시 JSON·코드 수정 없음.
- **월드 타일 임포트 규칙(v1.11)**: 바닥 타일(`Sprites/World/Tiles/{grass,dirt,path}.png`)은 64×32 px 마름모 1장, PPU 64, 피벗 중앙, Point 필터, 압축 없음, Full Rect. Tile 에셋은 `Assets/Tiles/<이름>.asset`. 울타리 칸(`fence.png`)은 기둥 + 오른쪽 위 1:2 가로대가 정확히 32px 오른쪽·16px 위까지, PPU 64, 피벗 = 기둥 밑 중앙. 기둥만(`fence_post.png`)은 피벗 하단 중앙. 개체 크기는 타일 1칸 기준으로 `animals.scale`·`VisitorTable.scale`로 맞춘다(웜뱃 0.6).
- **동물 아트 임포트 규칙(v1.7)**: 종마다 폴더 `Resources/Sprites/Animals/<종>/`. 정지 그림 `<종>.png`는 Single, 애니메이션 시트 `<종>_Idle.png`·`<종>_Move.png`는 가로 1행. 프레임은 **투명 열(4px 이상)로 나뉜 섬**을 하나씩 잡고, 폭은 가장 넓은 섬 + 2px로 통일해 각 섬의 가로 중심에 맞춘다(프레임 간격이 균등하지 않아도 되고, 몸의 가로 중심이 흔들리지 않는다). 이름 `<종>_Idle_0…`. **PPU는 Idle 시트 300을 기준으로, 다른 시트는 몸 높이(가장 낮은 불투명 행~가장 높은 불투명 행)가 Idle과 같아지도록 정규화**(예: 웜뱃 Move 400). 시트마다 그림 크기가 달라도 월드에서 같은 크기로 보인다. 큰 시트는 Max Size 4096. 파일명 대소문자는 JSON 경로와 정확히 같게(Android는 구분한다). 시트 피벗은 x = 섬의 가로 중심, **y = 그 시트에서 가장 낮은 불투명 픽셀 행(발끝) ÷ 높이**(프레임 아래 여백이 있어도 발이 땅에 닿는다. PPU 정규화와 함께 쓰면 상태 전환 때 발 위치·몸 크기가 유지된다). 크기 차이는 PPU가 아니라 `animals.scale`로 낸다. 슬라이스·피벗 계산은 에이전트가 CLI 스크립트로 한다(자동 슬라이스는 맞닿은 프레임을 합친다).
- **손님 시트 임포트 규칙(v1.15)**: `Resources/Sprites/Visitors/<종>/`에 정지 `<종>.png`(Single) + `<종>_Idle`·`_Move`·`_BackIdle`·`_BackMove`·`_SideIdle`·`_SideMove`(v1.22, 가로 1행, 칸 폭 104px(v1.18, 여우 걷기 104px), 발끝 = 아래 끝). 가게 유닛 크기(한 칸 2px, PPU 80, 스케일 1), 피벗 하단 중앙. 시트는 `Sprites/World/Shop/Source~/make_visitor_sheets.py`가 묶고, 슬라이스는 에디터 메뉴 `ZooTycoon/Bake/Import Visitor Sheets`.
- **행동 아이콘 임포트 규칙(v1.24)**: `Resources/Sprites/Actions/<행동 id>.png`, UI 스프라이트와 같이 1px = 1 UI px(PPU 25), Point, 비압축, Full Rect, 피벗 중앙, 9-slice 없음. 메뉴 `ZooTycoon/Bake/Import UI Sprites`가 이 폴더도 임포트한다. 실제 아트 생성은 `Sprites/UI/Source~/make_act_button.py`(버튼 바탕 `Sprites/UI/btn_act.png` 44×44 포함, 아이콘 18×18). auto 행동(`take_out`·`fill`·`serve`)은 아이콘 파일이 없다 — manual로 바꾸면 아이콘을 만들어 `icon`에 적는다. 버튼은 실행 중 `ActionTable.icon` 경로로 읽는다(프리팹에 아이콘 목록 없음)
- **굴 그림 재료 임포트 규칙(v1.30)**: 굴은 실행 중 한 장으로 칠한다(`BurrowPainter`). 재료 `Sprites/World/Shop/floor_tile.png`·`wall_tile.png`는 32×32, 윗벽 띠 `wall_face.png`(굴 환경 A2)는 64×40(0행 = 띠 윗변, 가로로만 이어짐). 셋 다 한 칸 = 1px, PPU 40, **Read/Write 켬**, Wrap Repeat, Point, 비압축, Full Rect, 피벗 왼쪽 위(`wall_tile`은 흙 배경 Tiled 스프라이트로도 쓴다). 띠 높이 40칸은 `BurrowShape.k_WallHeight`와 같아야 한다. 빈 자리 `slot_empty.png` PPU 40 피벗 중앙. 입구 아치 `arch.png` PPU 80, **피벗 아래 가운데 = 구멍 밑변 = 띠 밑변**(입구 줄 57칸 선, `BurrowShape.k_EntranceFloorTop`). 방 둘레 턱 6칸 색은 코드(`BurrowPainter.k_Ledge`). 생성은 `wall_face`·`wall_tile`·`arch` = `Shop/Source~/make_burrow_a.py`, `floor_tile`·`slot_empty` = `make_burrow_tiles.py`. 임포트는 `ZooTycoon/Bake/Shop`. 옛 구역 배경 4장(`entrance`·`shelf_row`·`counter_row`·`oven_row`)은 삭제

## 6. 변경 절차

1. 기획서의 해당 표/문단을 먼저 고친다(값의 출처는 항상 기획서).
2. JSON 값을 고친다. 구조가 바뀌면 `version` +1, 8장 스키마 표와 C# 행 클래스(`XXTable`)를 함께 고친다.
3. EditMode 테스트(테이블 검증)를 돌려 통과를 확인한다.
4. 미결이거나 가정한 값은 `notes`에 "기획서 n장 미결"로 남긴다.

에이전트 작업 규칙:
- JSON은 항상 파일 전체를 유효한 JSON으로 다시 쓴다(부분 문자열 치환으로 쉼표를 깨뜨리지 않는다).
- 행을 추가할 때 기존 ID·`sortOrder`를 바꾸지 않는다. 삭제는 행 제거가 아니라 `notes`에 사유를 적고 제거한다(세이브 호환은 코드가 "없는 ID 무시"로 처리).
- 값을 바꾸면 커밋 메시지나 보고에 "기획서 x.y 표 → 필드명 이전값→새값"을 적는다.

## 7. 검증 규칙 (테스트가 검사하는 것)

공통
- 파일이 유효한 JSON이고 `table`이 파일 이름과 같다, `id`가 비지 않고 유일하다, enum 칸이 아는 값이다 — `TableSet`이 읽을 때 예외(v1.34). `version`은 EditMode 테스트가 확인한다.
- 모든 행이 스키마의 필드를 전부 가진다(추가 필드가 있으면 경고).
- 문자열 `id`는 4장 패턴을 만족한다. 코드가 Id로 부르는 행은 모두 있다.

StringTable

- 코드가 쓰는 키가 전부 있는지는 컴파일러가 잡지 못하므로, 없는 키 조회는 런타임 예외로 드러낸다.

ConfigTable (v1.34 · v1.36)
- 코드 상수(`ConfigTable.k_*`)와 같은 id 8개가 모두 있다. `startCoins` ≥ 0, 나머지 `value` > 0. `carryCapacity`는 정수.

BakeryConfigTable (v1.34 · v1.36, 옛 `game_config.shop`)
- `bakery` 행이 있다. `checkoutSeconds`·`lookSeconds` > 0, `pickSeconds`·`patienceSeconds` ≥ 0, `maxCustomers`·`shelfCapacity` ≥ 1, `digBaseCost` > 0, `digCostGrowth` ≥ 1, `ovenBaseCost` > 0, `ovenCostGrowth` ≥ 1, `ovenMax` ≥ 시작 오븐 수(코드 `BakeryArea.k_StartOvens` = 1), `shelfBaseCost` > 0, `shelfCostGrowth` ≥ 1, `shelfMax` ≥ 시작 진열대 수(`BakeryArea.k_StartShelves` = 1).

PlazaConfigTable (v1.34, 옛 `game_config.plaza`)
- `main` 행이 있다. `cols`·`rows` ≥ 2, `arrivalSeconds` > 0, `maxVisitors` ≥ 1, `0 ≤ visitSecondsMin ≤ visitSecondsMax`, `0 ≤ visitsMin ≤ visitsMax`, `browseChance`·`emoteChance` 0~1.

PlazaDecorTable (v1.34, 옛 `game_config.plaza.decor`)
- `decoration`이 DecorationTable id.

ActionTable (v1.24 · v1.35)

InteractableTable (v1.24 · v1.35)
- 코드에 사물 클래스가 있는 id 7개(`shelf`·`oven`·`counter`·`slot`·`dig`·`exit`·`door`)가 모두 있다.
- `range > 0`. `actions`가 1개 이상이고 모두 ActionTable.json의 id. 붙인 행동을 그 사물이 받을 수 있다(EditMode 테스트).

DecorationTable (v1.32)

SoundTable (v1.26)
- 코드 상수와 같은 id 2개(`pay`·`oven_done`)가 모두 있다. `clip`이 비어 있지 않고 파일이 존재한다.

VisitorTable
- 행이 1개 이상. `id`는 `v` + 두 자리 번호(`v01`~).
- `sprite`가 비어 있지 않고 파일이 존재한다(`idleSheet`·`moveSheet`도 null이 아니면).

BreadTable

- `sprite`가 비어 있지 않다. `bakeSeconds > 0`, `price > 0`, `batchSize >= 1`, `weight >= 1`, `unlockCost >= 0`.

| `id` | string | 자동·버튼: `take_out`(오븐의 다 구운 빵을 `carryCapacity`까지 앞발에) · `fill`(든 빵을 그 빵 진열대에 자리만큼 한 번에. 빈 진열대는 그 빵 진열대 어디에도 자리가 없을 때만, v1.37) · `serve`(줄 머리 계산) · `open`(시트 열기, 돋보기) · `open_dig`(파기 시트 열기, 삽) · `exit`(빵집 구멍 앞 → 광장) · `enter`(광장 빵집 문 → 빵집. 둘 다 auto: 통로 range에 들어오면 바로, 들어온 직후는 한 번 벗어나야 다시. v1.38). 시트: `bake`(빵 고르기 + 다음 빵 해금 칩, 값은 `BreadTable.unlockCost`) · `upgrade`(사물 행의 업그레이드) · `place_shelf`(빈 진열대 설치, v1.37) · `place_oven`(오븐 설치) · `dig`(그 칸 파기) |

### 8.11 InteractableTable.json — 설계 09 v0.4 · 설계 13 웜뱃이 다루는 사물

**version 5** (v1.35: `upgrade` 데이터, `actions`에 시트 행동 · v1.34: 이름 규칙 · v1.32: `exit`·`door` 추가 · v1.24). 기준점(거리를 재는 곳)은 사물 클래스: 진열대·오븐 밑변, 계산대 뒤 웜뱃 자리, 빈 자리 표지, 팔 수 있는 흙 칸 사각형, 빵집 구멍 아래 바닥(`exit`), 광장 빵집 문 아래 바닥(`door`).

| 필드 | 타입 | 의미 |
|---|---|---|
| `id` | string | `shelf` · `oven` · `counter` · `slot` · `dig` · `exit` · `door` (각 사물 클래스의 `k_Id`) |
| `range` | number | 기준점에서 이 거리(유닛) 안이면 그 사물의 행동을 한다. range 안 사물 중 가장 가까운 것이 버튼 대상 |
| `actions` | string[] | 이 사물에서 할 수 있는 행동 전부(ActionTable.json id). 순서: manual은 버튼 우선순위, sheet는 시트 줄 순서 |
| `upgrade` | object\|null | 이 사물의 업그레이드(`upgrade` 행동의 데이터, v1.35). `name`·`baseCost`·`costGrowth`·`maxLevel`·`effectPerLevel`·`lookLevel`(이 단계부터 외형이 바뀜, 0 = 안 바뀜)·`effectFormat`(`{0}` 현재 `{1}` 다음). 비용 = baseCost × costGrowth^단계, 효과 = effectPerLevel × 단계. 단계는 사물 종류 공통, 값의 뜻은 사물 코드(오븐·계산대 = 속도 배수 1 + 효과, 진열대 = 용량 shelfCapacity + 효과) |

- 행동을 수동↔자동으로 바꾸기, 사물에 행동 붙이기·떼기, 거리·업그레이드 숫자 조정은 표만 고친다(코드·프리팹 그대로).

## 9. 이후 확장 시 규칙

- 빵 추가: `BreadTable.json`에 행 추가. version은 올리지 않는다(값 변경). 행 순서 = 해금 순서(오븐 시트에서 `unlockCost`로 연다). 진열대는 빵과 무관하게 빈 자리에서 사고, 어느 진열대든 첫 채움이 그 진열대의 빵이 된다(설계 17).
- 원격 설정: 같은 JSON을 서버에서 내려받아 로컬 파일보다 우선 적용. 형식은 바꾸지 않는다.
