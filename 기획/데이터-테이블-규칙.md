# 데이터 테이블 규칙

버전 v1.11 · 2026-09-16
게임 데이터(동물·등급·동물원 레벨·수식 상수)를 JSON 파일로 관리하는 규칙. 사람과 AI 에이전트가 이 문서를 보고 JSON을 만들고 고친다. 기획서(`동물원-타이쿤-기획서.md`)의 표가 "무엇을 넣을지"를 정하고, 이 문서는 "어떤 형태로 넣을지"를 정한다.

---

## 1. 결정 (2026-09-13)

| 항목 | 결정 |
|---|---|
| 원본 | JSON 파일이 유일한 원본. ScriptableObject는 쓰지 않는다 |
| 로드 | 게임 시작 시 `Resources.Load<TextAsset>`로 읽어 Newtonsoft.Json으로 C# 레코드에 역직렬화 |
| 파서 | Newtonsoft.Json (`com.unity.nuget.newtonsoft-json`) |
| 파일 구성 | 테이블당 파일 1개 |
| 에셋 참조 | JSON의 경로 칼럼(`Resources/` 기준)으로 `Resources.Load`. 더미 리소스를 먼저 두고 실제 리소스로 교체 (2026-09-14 변경) |
| 검증 | EditMode 테스트가 모든 테이블을 로드해 규칙(7장)을 검사한다. 테스트 실패 = 데이터 오류 |
| UI 문구 | 화면에 보이는 모든 문자열은 `strings.json`에서 온다. 코드·프리팹에 한국어 리터럴을 두지 않는다 (2026-09-14) |

## 2. 위치와 파일

```
ProjectTycoon/Assets/Resources/
├─ Data/
│  ├─ animals.json        동물 (기획서 6.1)
│  ├─ grades.json         등급과 가차 가중치 (6.1)
│  ├─ zoo_levels.json     동물원 레벨 해금 (6.4)
│  ├─ game_config.json    수식 상수·시작 상태 (6.2~6.4)
│  ├─ visitors.json       관광객 종류 (4장 관광객, v0.14)
│  ├─ facilities.json     시설·장식 (6.4 시설, v0.16)
│  └─ strings.json        UI 문구 (4장 화면 구성)
└─ Sprites/
   ├─ Animals/<종>/*.png     동물 아트 (animals.sprite·idleSheet·moveSheet 경로 칼럼으로 로드)
   ├─ Visitors/<종류>/*.png  관광객 아트 (visitors.sprite·idleSheet·moveSheet). 임포트 규칙은 동물과 같다(5장)
   └─ Facilities/<이름>/*.png 시설 아트 (facilities.sprite, 정지 1장, 피벗 하단 중앙)
```

- 파일 이름은 `snake_case.json`. 새 테이블을 추가하면 이 표와 8장 스키마에 함께 적는다.
- 런타임 저장 데이터(세이브 파일)는 테이블이 아니다. 여기 규칙을 따르지 않고 `Application.persistentDataPath`에 따로 둔다.

## 3. 공통 구조

행(row)이 여러 개인 테이블:

```json
{
  "table": "animals",
  "version": 1,
  "notes": ["사람/에이전트를 위한 메모. 로더는 무시한다."],
  "rows": [ { ... }, { ... } ]
}
```

상수 묶음(`game_config.json`)은 `rows` 대신 섹션 객체를 가진다 (8.4 참고).

| 필드 | 규칙 |
|---|---|
| `table` | 파일 이름(확장자 제외)과 같아야 한다. 로더가 잘못된 파일을 읽었는지 확인하는 용도 |
| `version` | 정수. **스키마(필드 구조)가 바뀔 때만** +1. 값만 바꿀 때는 올리지 않는다. 로더는 지원하지 않는 version이면 오류 |
| `notes` | 문자열 배열. 선택. 미결 항목·출처·주의점을 적는다. JSON은 주석이 없으므로 주석 대용 |
| `rows` | 행 배열. 순서는 `sortOrder`가 따로 있으면 무시되고, 없으면 파일 순서가 표시 순서 |

## 4. 표기 규칙

- **키**: `camelCase`. 영어만. 축약하지 않는다 (`baseIncomePerSecond`, `incPerSec` ✗).
- **ID**: 문자열, `^[a-z][a-z0-9_]*$`. 등급·모드 같은 열거형 값도 소문자 문자열(`"common"`, `"refundCoins"`는 예외적으로 camelCase 허용 — 코드 enum 이름과 맞추기 위함). 동물 ID는 `a` + 두 자리 번호(`a01`~`a99`). 번호는 재사용하지 않는다(삭제된 종의 번호는 비워 둔다).
- **표시 이름**: `name`에 한국어. 다국어를 도입하면 `nameKey`로 바꾸고 `name`을 지운다(version +1).
- **숫자**: 배수·비율은 소수(`0.5` = +50%), 퍼센트 정수를 쓰지 않는다. 확률은 **가중치**(정수)로 적고 로더가 합으로 나눈다. 시간은 초 단위 정수. 코인은 정수(내부 계산은 double).
- **불리언**: `true/false`. 0/1을 쓰지 않는다.
- **없음**: `null`. 필드를 생략하지 않는다 — 모든 행은 같은 필드 집합을 가진다(누락 검출을 위해).
- **색**: `"#RRGGBB"` 문자열.
- 들여쓰기 2칸, UTF-8, LF, 파일 끝 개행.

## 5. 에셋 참조 규칙 (2026-09-14 변경)

에셋은 JSON의 **경로 칼럼**으로 가리킨다. 값은 `Resources/` 아래 상대 경로(확장자 없음)이며 코드가 `Resources.Load(path)`로 읽는다. 이름을 바꾸거나 다른 파일로 바꿀 때 JSON 값만 고치면 된다.

| 에셋 | 칼럼 | 값 예 | 없을 때 |
|---|---|---|---|
| 동물 정지 그림·시트 | `animals.sprite`, `idleSheet`, `moveSheet` | `Sprites/Animals/Wombat/Wombat_Idle` | 검증 실패(테스트) |
| 등급 색 | `grades.colorHex` | `#42A5F5` (에셋 아님) | — |
| UI 프리팹 | 칼럼 없음. GameKit `UIManager`가 `UI/{뷰 타입 이름}` 규칙으로 로드 | `Resources/UI/GachaButtonView` | — |

- 개발 중에는 에이전트가 경로 자리에 **더미 리소스**(단색 스프라이트 등)를 만들어 둔다. 사용자가 같은 경로·이름의 실제 리소스로 덮어써 교체한다. 교체 시 JSON·코드 수정 없음.
- **월드 타일 임포트 규칙(v1.11)**: 바닥 타일(`Sprites/World/Tiles/{grass,dirt,path}.png`)은 64×32 px 마름모 1장, PPU 64, 피벗 중앙, Point 필터, 압축 없음, Full Rect. Tile 에셋은 `Assets/Tiles/<이름>.asset`. 울타리 칸(`fence.png`)은 기둥 + 오른쪽 위 1:2 가로대가 정확히 32px 오른쪽·16px 위까지, PPU 64, 피벗 = 기둥 밑 중앙. 기둥만(`fence_post.png`)은 피벗 하단 중앙. 개체 크기는 타일 1칸 기준으로 `animals.scale`·`visitors.scale`로 맞춘다(웜뱃 0.6).
- **동물 아트 임포트 규칙(v1.7)**: 종마다 폴더 `Resources/Sprites/Animals/<종>/`. 정지 그림 `<종>.png`는 Single, 애니메이션 시트 `<종>_Idle.png`·`<종>_Move.png`는 가로 1행. 프레임은 **투명 열(4px 이상)로 나뉜 섬**을 하나씩 잡고, 폭은 가장 넓은 섬 + 2px로 통일해 각 섬의 가로 중심에 맞춘다(프레임 간격이 균등하지 않아도 되고, 몸의 가로 중심이 흔들리지 않는다). 이름 `<종>_Idle_0…`. **PPU는 Idle 시트 300을 기준으로, 다른 시트는 몸 높이(가장 낮은 불투명 행~가장 높은 불투명 행)가 Idle과 같아지도록 정규화**(예: 웜뱃 Move 400). 시트마다 그림 크기가 달라도 월드에서 같은 크기로 보인다. 큰 시트는 Max Size 4096. 파일명 대소문자는 JSON 경로와 정확히 같게(Android는 구분한다). 시트 피벗은 x = 섬의 가로 중심, **y = 그 시트에서 가장 낮은 불투명 픽셀 행(발끝) ÷ 높이**(프레임 아래 여백이 있어도 발이 땅에 닿는다. PPU 정규화와 함께 쓰면 상태 전환 때 발 위치·몸 크기가 유지된다). 크기 차이는 PPU가 아니라 `animals.scale`로 낸다. 슬라이스·피벗 계산은 에이전트가 CLI 스크립트로 한다(자동 슬라이스는 맞닿은 프레임을 합친다).
- 검증기는 경로 칼럼이 비어 있지 않은지만 검사한다. 파일 존재는 EditMode 테스트가 `Assets/Resources/<path>.*` 로 확인한다.
- v1.0의 "ID 규칙 경로" 방식은 폐기. 이유: 실제 리소스 교체 시 이름을 ID에 맞추는 부담을 없애고, 한 종이 여러 에셋(스프라이트·아이콘·사운드)을 갖게 될 때 칼럼만 늘리면 되게 하기 위함.

## 6. 변경 절차

1. 기획서의 해당 표/문단을 먼저 고친다(값의 출처는 항상 기획서).
2. JSON 값을 고친다. 구조가 바뀌면 `version` +1, 8장 스키마 표와 C# 레코드를 함께 고친다.
3. EditMode 테스트(테이블 검증)를 돌려 통과를 확인한다.
4. 미결이거나 가정한 값은 `notes`에 "기획서 n장 미결"로 남긴다.

에이전트 작업 규칙:
- JSON은 항상 파일 전체를 유효한 JSON으로 다시 쓴다(부분 문자열 치환으로 쉼표를 깨뜨리지 않는다).
- 행을 추가할 때 기존 ID·`sortOrder`를 바꾸지 않는다. 삭제는 행 제거가 아니라 `notes`에 사유를 적고 제거한다(세이브 호환은 코드가 "없는 ID 무시"로 처리).
- 값을 바꾸면 커밋 메시지나 보고에 "기획서 x.y 표 → 필드명 이전값→새값"을 적는다.

## 7. 검증 규칙 (테스트가 검사하는 것)

공통
- 파일이 유효한 JSON이고 `table`이 파일 이름과 같다. `version`이 코드가 지원하는 값이다.
- 모든 행이 스키마의 필드를 전부 가진다(추가 필드가 있으면 경고).
- `id`는 테이블 안에서 유일하고 4장 패턴을 만족한다. `sortOrder`는 유일하다.

animals
- `grade`가 `grades.rows[].id` 중 하나다.
- `baseIncomePerSecond > 0`, `gachaWeight >= 1`(정수).
- (v1.7 삭제) "등급별로 최소 1종" — 종이 한 개뿐인 동안은 성립하지 않는다. 빈 등급은 확률 0.
- `sprite`가 비어 있지 않고 `Assets/Resources/{sprite}.*` 파일이 존재한다. `idleSheet`·`moveSheet`도 null이 아니면 파일이 존재한다.
- `frameRate > 0`, `scale > 0`, `moveSpeed > 0`, `0 ≤ idleSecondsMin ≤ idleSecondsMax`.

grades
- `gachaWeight >= 0`(정수), 합 > 0.
- 계산된 확률(가중치/합)을 기획서 6.1 표와 비교해 `notes`에 기록.

zoo_levels
- `level`이 1부터 연속 정수. `requiredTotalCoins`가 레벨 순으로 단조 증가(같은 값 허용 안 함). 첫 레벨은 `requiredTotalCoins == 0`.
- (v1.10 삭제) `cageCount` 단조 증가, `unlocksPromotion` 정확히 1개 — 두 칼럼 모두 삭제됨

strings
- `id`가 유일하고 4장 패턴을 만족한다(밑줄 표기, 점 금지). `ko`가 비어 있지 않다.
- 코드가 쓰는 키가 전부 있는지는 컴파일러가 잡지 못하므로, 없는 키 조회는 런타임 예외로 드러낸다.

game_config
- `gacha.costGrowth > 1`, `gacha.baseCost > 0`. (v1.10) `promotion` 섹션 삭제 — 홍보는 facilities 첫 행
- `animalCount.incomeBonusPerAnimal >= 0`.
- `offline.maxSeconds > 0`. `start.coins >= gacha.baseCost`(첫 뽑기가 가능해야 함).
- `visitors.maxCount >= 1`, `visitors.incomeUnit > 0`.

visitors
- 행이 1개 이상. `id`는 `v` + 두 자리 번호(`v01`~).
- `sprite`가 비어 있지 않고 파일이 존재한다(`idleSheet`·`moveSheet`도 null이 아니면). `weight >= 1`(정수).
- `frameRate > 0`, `scale > 0`, `moveSpeed > 0`, `0 ≤ viewSecondsMin ≤ viewSecondsMax`.

facilities
- 행이 1개 이상. `id`는 `f` + 두 자리 번호(`f01`~).
- `sprite`가 비어 있지 않고 파일이 존재한다.
- `unlockLevel`이 `zoo_levels.rows[].level` 중 하나. `maxStage >= 1`(정수). `multiplierPerStage > 0`. `baseCost > 0`, `costGrowth > 1`.
- `slotX`·`slotZ`는 검사하지 않는다(월드 연출 숫자. 우리 안 모서리에 두는 것은 설계 07 P7).
- 열거형 문자열이 허용 값 안에 있다(8.4 표).

## 8. 테이블 스키마

### 8.1 animals.json — 기획서 6.1

**version 2** (v1.7: 연출·행동 값 7개 추가).

| 필드 | 타입 | 의미 |
|---|---|---|
| `id` | string | 동물 ID (`a01`~) |
| `name` | string | 표시 이름(한국어) |
| `grade` | string | 등급 ID (`grades.id`) |
| `baseIncomePerSecond` | number | 레벨 1 초당 수입 |
| `gachaWeight` | int | 같은 등급 안에서의 상대 가중치. 기본 1 |
| `sprite` | string | 정지 그림 경로(`Resources/` 기준, 확장자 없음). 결과 카드·도감용 |
| `idleSheet` | string∣null | 대기 애니메이션 시트 경로. null이면 `sprite` 1장 |
| `moveSheet` | string∣null | 이동 애니메이션 시트 경로. null이면 `sprite` 1장 |
| `frameRate` | number | 초당 프레임 |
| `scale` | number | 개체 크기 배율(그림자 포함) |
| `moveSpeed` | number | 이동 속도(유닛/초) |
| `idleSecondsMin`, `idleSecondsMax` | number | 도착 후 멈춰 있는 시간 범위(초) |
| `variantId` | string∣null | 색깔 변형 ID. 첫 버전은 항상 null (예비 칸) |
| `sortOrder` | int | 도감 표시 순서 |

개별 동물의 뽑기 확률 = (등급 가중치 / **동물이 있는 등급의** 가중치 합) × (동물 가중치 / 같은 등급 동물 가중치 합).
예: 웜뱃만 있으면 70/70 × 1/1 = 100%. 8종이면 토끼 = 70/100 × 1/4 = 17.5%.

| 필드 | 타입 | 의미 |
|---|---|---|
| `level` | int | 동물원 레벨(1부터) |

### 8.4 game_config.json — 기획서 6.2~6.4

`rows` 없이 섹션 객체. **version 7** (v1.4: `cageGrid` 삭제, v1.5: `gacha.costBasis` 삭제, v1.6: `income` 추가, v1.8: `visitors` 추가·`promotion.visitorsPerStage` 삭제, v1.9: `animalLevel` → `animalCount`, v1.10: `promotion` 삭제).

|---|---|---|---|

| `animalCount.incomeBonusPerAnimal` | number | 마리당 수입 배수 증가 (`1 + bonus × (마리 수 − 1)`) | 6.2 |

### 8.7 strings.json — 기획서 4장

| 필드 | 타입 | 의미 |
|---|---|---|
| `id` | string | 문구 키. `화면_요소` 밑줄 표기(`topbar_coins`). 4장 ID 패턴을 따른다 |
| `ko` | string | 한국어 문구. `{0}`, `{1}` 플레이스홀더는 `string.Format` 인자 순서 |

- 코드는 `StringTable.Get(id)` / `Format(id, args)`로만 문자열을 얻는다. `[SerializeField]`로 박은 텍스트, 코드 리터럴 모두 금지.
- 숫자는 호출부에서 먼저 문자열로 만든다(`BigNumberFormatter`, `N0`). 문구 테이블은 숫자 서식을 모른다.
- 다국어를 도입하면 `en` 칸을 추가하고 로더가 언어를 골라 읽는다(version +1). 첫 버전은 `ko` 하나.

## 9. 이후 확장 시 규칙

- 종 추가: `animals.json`에 행 추가. 시설 추가: `facilities.json`에 행 추가(자리는 카메라 팬 범위 안). version은 올리지 않는다(값 변경).
- 색깔 변형: `variants.json` 신설(`id`, `name`, `hueShift`, `gachaWeight`). `animals.variantId`는 그대로 두고 변형 개체는 세이브 쪽에서 표현.
- 고유 효과: `animals`에 `effectId`(null 허용) 필드 추가 → version 2. `effects.json` 신설.
- 원격 설정: 같은 JSON을 서버에서 내려받아 로컬 파일보다 우선 적용. 형식은 바꾸지 않는다.
