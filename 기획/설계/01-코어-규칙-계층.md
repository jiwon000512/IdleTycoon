# 설계 01 — 코어 규칙 계층 (Core + Data + 테스트)

상태: 검토 중 · 2026-09-14
범위: 게임 규칙 전체를 순수 C#로 구현하고 EditMode 테스트로 기획서 숫자를 검증한다. 화면·저장 호출·틱은 다음 작업(설계 02: Game + UI)에서.
기획서 대응: 3장(핵심 루프), 6.1~6.4(데이터·수식), 데이터-테이블-규칙 7장(검증)

## 1. 코드 설계

### 1.1 계층 조정

코드-규칙 2장에서 "Data = 레코드 + 검증기"로 두었으나, Core 서비스가 레코드(`AnimalRecord` 등)를 직접 읽어야 하므로 **레코드와 테이블 묶음(`GameTables`)을 Core로 옮긴다.** Data는 검증기만 갖는다. (Data → Core 의존은 그대로. Core는 아무것도 참조하지 않음.)

| asmdef | 이번 작업에서 만드는 것 |
|---|---|
| `ZooTycoon.Core` | 레코드 4종, `GameTables`, `ZooState`, 서비스 4개, 계산기 2개, `SaveData`, 경계 인터페이스 2개 |
| `ZooTycoon.Data` | `TableValidator` |
| `ZooTycoon.Tests.EditMode` | 테스트 7파일 + 대역 2개 |

### 1.2 클래스

| # | 계층 | 클래스 | 책임 | 의존 | 기획서 |
|---|---|---|---|---|---|
| 1 | Core/Tables | `AnimalRecord`, `GradeRecord`, `ZooLevelRecord`, `GameConfig` | JSON 행과 1:1 DTO. `GameConfig`는 섹션 클래스(`StartConfig`, `CageGridConfig`, `GachaConfig`, `AnimalLevelConfig`, `PromotionConfig`, `OfflineConfig`) 중첩 | 없음 | 6.1~6.4 |

| 3 | Core | `IClock` (`DateTime UtcNow`), `IRandom` (`double NextDouble()`) | 외부 경계 | 없음 | — |
| 4 | Core | `ZooState` | 상태 소유: `Coins`, `TotalCoinsEarned`, `PullCount`, `PromotionStage`, `PlacedAnimals`(id→level, 배치 순서 유지), `WaitingRoom`(id 목록), `LastSavedAtUtc`. 변경 메서드: `AddCoins`, `TrySpendCoins`, `IncrementPull`, `PlaceAnimal`, `LevelUpAnimal`, `EnqueueWaiting`, `DequeueWaiting`, `SetPromotionStage`. 이벤트 `CoinsChanged(double)` | 없음 | 6.4 시작 상태 |

| 7 | Core | `ZooLevelService` | `Level`, `CageCount`, `NextThreshold`, `IsPromotionUnlocked`. `Refresh()`: `TotalCoinsEarned`로 레벨 재계산, 오르면 대기실 동물을 빈 우리에 자동 입장. 이벤트 `ZooLevelReached(int)` | 2, 4 | 6.4 |
| 8 | Core | `PromotionService` | `Multiplier` = 1 + m × stage, `NextCost` = base × growth^stage, `IsMaxed`, `bool TryUpgrade()`(해금·코인·최대 단계 검사). 이벤트 `PromotionUpgraded(int)` | 2, 4, 7 | 6.4 |
| 9 | Core | `IncomeService` | `IncomePerSecond`, `Tick(double deltaSeconds)`: 수입 × dt를 `AddCoins` | 2, 4, 5, 8 | 3장 |
| 10 | Core | `OfflineIncomeCalculator` (static) | `Calculate(incomePerSecond, elapsedSeconds, capSeconds)` | 없음 | 6.4 |
| 11 | Core | `PullResult` (readonly struct) | `AnimalId`, `IsNewSpecies`, `Level`, `IsPlaced` | 없음 | — |
| 12 | Core | `SaveData` | 세이브 DTO(`ZooState`와 같은 필드, 컬렉션은 List). `ZooState.ToSaveData()`, `ZooState.FromSaveData(dto)` | 4 | 8장 |
| 13 | Data | `TableValidator` (static) | `IReadOnlyList<string> Validate(GameTables)`: 데이터-테이블-규칙 7장 규칙(ID 유일·패턴, grade 참조, 가중치·수입 범위, 등급별 1종 이상, 레벨 연속·단조 증가, 홍보 해금 1개, 격자 ≥ 우리 수, 비용·성장률 범위, 시작 코인 ≥ 첫 비용) | 1, 2 | 규칙 7장 |

의존 방향: 9 → 8 → 7 → 4 · 6 → 7. 순환 없음. 모든 서비스는 생성자로 `ZooState`, `GameTables`(필요 시 `IRandom`, 다른 서비스)를 받는다. 이벤트는 C# `event Action<T>`.

### 1.3 공개 API 요약

```csharp
// 조립 (설계 02의 GameBootstrap이 함)
var tables = new GameTables(animals, grades, zooLevels, config);
var state = ZooState.CreateNew(tables.Config);            // 코인 300, 동물 0
var zooLevel = new ZooLevelService(state, tables);
var promotion = new PromotionService(state, tables, zooLevel);
var gacha = new GachaService(state, tables, zooLevel, random);
var income = new IncomeService(state, tables, promotion);

// 루프
income.Tick(0.2); zooLevel.Refresh();
if (gacha.TryPull(out PullResult result)) { /* result.IsNewSpecies ... */ }
promotion.TryUpgrade();
double offline = OfflineIncomeCalculator.Calculate(income.IncomePerSecond, elapsed, tables.Config.Offline.MaxSeconds);
```

### 1.4 규칙 적용

- Core·Data는 `noEngineReferences`. `DateTime.UtcNow`·`System.Random` 직접 사용 없음.
- 숫자는 전부 `GameConfig`·테이블에서. 코드 상수 없음.
- 실패는 `TryXxx` 반환값. 예외는 생성자 인자 오류·잘못된 ID 조회에만.
- 주석 최소. 기획서 표 번호만 남긴다.
