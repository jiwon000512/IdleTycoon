# 설계 04 — 수입 틱과 GameManager

상태: 구현 완료 · 2026-09-14
기능: 보유 동물의 초당 수입이 코인으로 쌓인다. 누적 코인이 기준을 넘으면 동물원 레벨이 오른다. 코인이 부족하면 가차 버튼에 "n초 후"가 보인다. 부트스트랩 구조를 `GameManager`(싱글턴) + `MainScene`(씬 스크립트)으로 바꾼다.
기획서 대응: 3장 루프 3·5, 4장 상단 바·큰 가차 버튼(남은 시간), 6.2 총 수입, 6.4 동물원 레벨, 8장 숫자
다음 기능: 05 관광객

---

## 0. 결정

### 0.1 사용자 확정 (2026-09-14)

| # | 결정 | 이유 |
|---|---|---|
| D1 | **`GameBootstrap` 폐지.** 씬에는 씬 이름 스크립트 `MainScene`을 두고, `Awake`에서 `GameManager.Instance.Init()`만 부른 뒤 이 씬에 필요한 것(상단 바·가차 버튼·월드 Presenter 생성)만 한다 | 사용자 지시. 씬 스크립트는 씬 전용 조립, 게임 전체 상태는 GameManager |
| D2 | **`GameManager : MonoSingleton<GameManager>`**(Game 계층). `Init()`에서 `TableManager`로 테이블 로드·검증, `ZooState`·서비스 생성. `Update`에서 수입 틱. UI는 이것을 참조한다 | 사용자 지시. 씬이 여러 개가 되어도 상태가 한 곳에 산다 |

### 0.2 설계 제안 (검토 필요)

| # | 제안 | 이유 |
|---|---|---|
| P1 | **UI(Presenter)는 `GameManager`를 직접 부르지 않고, `MainScene`이 `GameManager.Instance`의 서비스를 Presenter 생성자에 넘긴다** | asmdef가 `Game → UI`다. UI가 `GameManager`(Game)를 참조하면 순환이라 컴파일이 안 된다. "UI가 참조"는 MainScene을 거쳐 만족한다. Presenter 코드는 한 줄도 안 바뀐다 |
| P2 | **틱 = 1초에 한 번**(사용자 확정 2026-09-14). `GameManager.Update`가 `Time.deltaTime`을 누적해 `income.tickSeconds`(game_config, 1) 이상이면 `Tick(누적)`. 숫자 보간 없음 | 틱 간격은 기획 숫자라 `game_config.income.tickSeconds`에 둔다(version 4). 기획서 8장·CLAUDE.md의 "0.1~0.25초 틱 + 보간" 문구를 "1초 틱, 보간 없음"으로 고친다 |
| P3 | `IncomeService.Tick(dt)`: `state.AddCoins(TotalIncomePerSecond × dt)` 후 `zooLevelService.Refresh()` | 코드-규칙 8장 지도 그대로. 레벨업이 적립과 같은 틱에 일어난다 |
| P4 | 남은 시간 = `(비용 − 코인) ÷ 초당 수입`. `GachaService.SecondsUntilAffordable`. 살 수 있으면 0, 수입 0이면 `PositiveInfinity` | 수식은 서비스에(코드-규칙 3장) |
| P5 | 버튼 안 비용 아래 TMP 1개(`m_waitText`). 살 수 있거나 무한대면 빈 문자열, 아니면 `{0}초 후`(올림). 분 단위 분기 없음 | 비용은 상시 표시라 자리를 뺏지 않는다. n=40에서 "120초 후"도 읽힌다 |
| P6 | 갱신은 기존 `CoinsChanged` 구독으로 충분(틱마다 발생). 변경 감지·캐시 없음 | 텍스트 2~3개 `SetText`는 비용이 아니다 |
| P7 | `GameManager`는 `Init()` 전에 `Update`가 돌지 않도록 `m_income != null`만 본다. 그 외 순서 가드 없음 | 프로그래밍-규약 10장 "호출 순서 가드는 두지 않는다"에 맞춘 최소 |
| P8 | `GameBootstrap.cs`를 `MainScene.cs`로 **git mv**(meta GUID 유지) → 씬의 컴포넌트·`m_worldView` 참조가 그대로 산다. 씬 오브젝트 이름만 `MainScene`으로 | 씬 파일 수정 최소 |
| P9 | 규칙 문서 갱신: 코드-규칙 3장 "싱글턴 금지" 예외에 `GameManager` 추가, 4장 Game·8장 지도의 `GameBootstrap`/`GameTicker` → `GameManager`/`MainScene`. CLAUDE.md 코드 규칙·기술 결정 행 동일 | 규칙과 코드가 어긋난 채 두지 않는다 |

## 1. 코드 설계

### 1.1 계층

asmdef·참조 변경 없음. `GameManager`·`MainScene`은 Game.

### 1.2 클래스

| # | 계층 | 클래스 | 책임 · 공개 API | 상태 |
|---|---|---|---|---|
| 1 | Core | `IncomeService` | 생성자 `(ZooState, GameTables, ZooLevelService)`. `void Tick(double dt)`(P3) | 신규 |
| 2 | Core | `GachaService` | 추가 `double SecondsUntilAffordable`(P4) | 수정 |
| 3 | Game | `GameManager : MonoSingleton<GameManager>` | `Init()`: 테이블 로드·검증(실패 시 예외) → `ZooState.CreateNew` → `ZooLevelService` → `GachaService(SystemRandom)` → `IncomeService`. 프로퍼티 `Tables`, `State`, `ZooLevel`, `Gacha`. `Update`: `deltaTime` 누적, `tickSeconds` 이상이면 `m_income.Tick(누적)`(P2·P7) | 신규 |
| 4 | Game | `MainScene : MonoBehaviour` | `[SerializeField] WorldView m_worldView`. `Awake`: `GameManager.Instance.Init()` → `Open<TopBarView>`·`Open<GachaButtonView>` → Presenter 4개 생성(P1). `OnDestroy`: `Dispose` 4개 | `GameBootstrap` 이름 변경(P8) |
| 5 | UI | `GachaButtonView` | `[SerializeField] TMP_Text m_waitText`, `SetWait(string)` | 수정 |
| 6 | UI | `GachaButtonPresenter` | `Refresh`에서 `SetWait`(P5) | 수정 |

### 1.3 흐름

```
MainScene.Awake
  GameManager.Instance.Init()      테이블 → 상태 → 서비스
  UIManager.Open<TopBarView>, <GachaButtonView>
  new TopBarPresenter(view, gm.State, gm.ZooLevel, gm.Tables) …

GameManager.Update
  누적 deltaTime ≥ tickSeconds → m_income.Tick(누적)    AddCoins → CoinsChanged → 상단 바·버튼 갱신
                                   Refresh → ZooLevelReached → 상단 바 레벨 갱신
```

### 1.7 규칙 적용과 예외

- `GameManager`는 코드-규칙 3장 "싱글턴 금지"의 예외(D2). 게임 규칙은 여전히 Core 서비스에 있고, `GameManager`는 생성·보관·틱 호출만 한다.
- `MainScene`은 씬 전용 조립. `new`는 `GameManager.Init`(서비스)과 `MainScene`(Presenter) 두 곳.

## 3. 구현 결과 (2026-09-14)

| # | 달라진 점 | 이유 |
|---|---|---|
| C1 | `IncomeService.Tick`에 "수입 0이면 아무것도 안 함" 분기를 넣지 않았다 | `AddCoins(0)`은 상태를 안 바꾸고 이벤트만 한 번 더 낸다. 분기 4줄 값어치가 없다 |
| C2 | `GameManager`의 `m_income == null` 가드(P7)는 유지 | `Init()`이 예외로 중단되면 `Update`가 매 프레임 NRE를 내는 것을 막는다 |

검증: 컴파일 0 · 콘솔 0 · EditMode 80/80 · 플레이: 3회 뽑기 후 코인 13 → 매초 적립(2021.01), 버튼 `62초 후` = ⌈(140−17)/2⌉, 코인 2,000 주입 후 다음 틱에 `Lv.2`·`2,008/8,000`, 살 수 있게 되면 문구 사라지고 버튼 활성.
