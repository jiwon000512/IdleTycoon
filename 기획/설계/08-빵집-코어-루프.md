# 설계 08 — 빵집 코어 루프 (사업가 웜뱃, 첫 업종)

초안 v0.2 · 2026-09-18 · 사용자 확정 전. v0.1 → v0.2: 사용자 의도 확인 — **존(굴 입구)을 누르면 가게 내부 화면으로 전환**되는 두 화면 구조. Core는 v0.1과 같고 World·UI만 바뀌었다. 기획 출처: 「사업가 웜뱃」 기획서 아티팩트 02·03·04장(https://claude.ai/artifact/TQaPKFEcLafuVm4WNitbGv), 7회차 05-4 빵집 러시. 확정되면 기획서 v0.23에 옮긴다. 이전 `08-존-입주-번식.md`는 이 문서로 대체한다(확정 시 삭제).

**이 기능의 목적**: 30초 루프(줄이 차오른다 → 카운터가 녹인다 → 종을 치면 러시 → 문 밖으로 밀리기 전에 받아 낸다 → 쿵)를 실제 코드 구조 안에서 만들어 사용자가 3분 플레이하고 "끌리나"를 판정한다. 직원·벽·굴 지도는 09~12.

### 1.1 두 화면

- **지상(기존)**: 쿼터뷰 존 맵. 08에서는 굴 입구 지도 역할만 한다. 존 z01이 빵집. 존을 탭하면 내부로. 동물·관광객·시설 카드는 지상에 세우지 않는다(코드는 남기고 `MainScene`이 안 부른다).
- **내부(신규)**: 순수 2D 한 화면 가게(기획서 05-4 화면 구성). 세로 1080×1920, 카메라 직교 size 6 그대로(폭 6.75 × 높이 12유닛). 위에서 아래로: 거리·출입문 → 홀(줄 발자국 10칸, 뱀 모양 3줄) → 카운터 3 → 오븐·진열대 → HUD.

내부 화면 좌표(논리 = 화면 XY, Iso 변환 없음):

| 요소 | 위치(유닛) |
|---|---|
| 출입문(손님 진입점) | (0, +4.6) |
| 웜뱃(주인공, 문 옆) | (+2.4, +4.2) |
| 줄 10칸 | 1행 y +3.2: x −2.4 … +2.4 (4칸, 왼→오) · 2행 y +2.0: x +2.4 … −2.4 (4칸, 오→왼) · 3행 y +0.8: x −2.4, −0.8 (2칸) |
| 카운터 1·2·3 | (−2.0, −1.2) · (0, −1.2) · (+2.0, −1.2). 손님 자리 = 카운터 + (0, +0.9) |

| 퇴장 | 카운터에서 문으로 되돌아 걸어 화면 밖 (+0, +6) |

### 1.2 전환

- 같은 씬, 같은 카메라. 내부 프리팹 `Shop.prefab`은 월드 (1000, 0)에 둔다. 존 탭 → 카메라가 (1000, 0)으로 점프, 드래그 잠금. 뒤로 → 카메라를 지상 초점으로 복귀, 드래그 해제. 08은 연출 없이 즉시.
- "지금 어느 화면인가"는 Core의 `Navigation`이 갖는다(아래 2.2). UI와 World가 둘 다 이 이벤트를 본다. UI와 World가 서로 알지 않아도 되게 하는 장치다.

### 2.1 계층 배치

의존은 지금과 같다: `Game → UI/World/Data → Core`. UI와 World는 서로 모르고 둘 다 `ShopSim`·`Navigation` 이벤트만 본다. **v0.1 대비 Core 변경은 `Navigation` 한 클래스뿐**이고, 규칙 시뮬은 화면이 어디든 같다. 이것이 "규칙은 Core, 화면은 World"가 지켜지는지의 첫 확인이다.

### 2.2 Core 상세

```csharp
// Core/Shop/ShopSim.cs — 게임 규칙의 단일 소유자. UnityEngine 없음
public sealed class ShopSim
{
    public ShopSim(ZooState state, FacilityService facility, GameTables tables, BakeryRule rule, IRandom random);

    public IReadOnlyList<Customer> Queue { get; }        // 줄 (앞에서부터)
    public IReadOnlyList<Counter> Counters { get; }      // 3자리
    public int QueueCapacity { get; }                    // 10
    public bool IsRushing { get; }
    public double RushRemaining { get; }                 // 초
    public int RushIndex { get; }                        // 통과한 러시 수 + 1
    public double SlamRemaining { get; }                 // 문 막기 남은 초

    public void Tick(double dt);                         // GameManager가 1초마다
    public bool TryStartRush();                          // 종. 러시 중이면 false
    public bool TrySlam();                               // 쿵. 쿨다운 중이면 false
    public bool TryServe(int counterIndex);              // 카운터 탭: 처리 중이면 즉시 완료

    public event Action<Customer, int> CustomerArrived;  // (손님, 줄 위치)
    public event Action QueueChanged;                    // 줄 순서·길이 변화 (View는 Queue를 다시 읽는다)
    public event Action<Customer, int> CustomerServing;  // 카운터로 이동
    public event Action<Customer, double> CustomerServed;// 코인 지급됨
    public event Action<Customer> CustomerLeft;          // 문 밖으로 밀려 나감(러시 실패 시 뒤쪽 손님)
    public event Action RushStarted;
    public event Action<bool> RushEnded;                 // 통과 여부
    public event Action SlamStarted;
}

// Core/Navigation.cs — 현재 화면. 규칙이 아니라 "어디를 보고 있나"지만 UI·World가 공유해야 해서 Core
public sealed class Navigation
{
    public Screen Current { get; }                       // Overworld | Shop
    public void EnterShop();                             // 08은 굴이 하나라 인자 없음. 12에서 zoneId
    public void ExitShop();
    public event Action Changed;
}
```

`Tick(dt)` 한 번의 순서(이 순서가 규칙이다):

1. 쿵·러시 타이머 감소.
2. **도착**: `rule.ArrivalsThisTick(state, dt, random)`만큼 `Customer` 생성 → 줄 뒤에 붙인다. 줄이 상한을 넘으면 넘친 손님은 `CustomerLeft`, 러시 중이면 **즉시 실패**(`RushEnded(false)`, 러시 종료, 남은 줄은 유지).
3. **처리**: 카운터마다 `remaining -= dt × speed(단계)`. 0 이하면 `CustomerServed(c, rule.Value(c, oven단계))` → `state.AddCoins`. 빈 카운터에 줄 머리를 배정(`CustomerServing`).
4. **러시 종료**: `RushRemaining ≤ 0`이면 통과(`RushEnded(true)`, `RushIndex++`). 통과 조건은 "60초 동안 문 밖으로 안 밀렸다"뿐이라 남은 줄은 그대로 녹는다.

시뮬은 화면과 무관하게 돈다. 지상에 있어도 빵집 줄은 차고 처리된다(러시는 내부에서만 시작할 수 있다).

```csharp
// Core/Shop/BakeryRule.cs — 두 번째 업종이 올 때 IShopRule로 뽑힐 경계. 08에서는 구체 클래스 하나
public sealed class BakeryRule
{
    public BakeryRule(ShopConfig config);
    public int ArrivalsThisTick(ShopState s, double dt, IRandom r); // 평시 분당 n, 러시 중 60초에 45명 (+ 러시마다 증가), 쿵 중 0
    public double Value(Customer c, int ovenStage);                // 단가 × Π(1 + oven.multiplierPerStage × 단계)
    public double SlamSeconds { get; }                             // 5
    public double SlamCooldown { get; }                            // 20
}
```

**경계 규칙**: `ShopSim`은 `BakeryRule`의 위 4개 멤버만 부른다. 다른 업종의 규칙(도장·깊이·낮밤)이 `ShopSim` 본체에 `if`로 들어가면 안 되고, 들어가야 한다면 그 시점(13)에 `IShopRule`을 뽑는다. 08에서 인터페이스를 미리 만들지 않는 이유는 구현 하나짜리 인터페이스를 두지 않는 규칙(코드-규칙 3장) 때문이며, 추출은 메서드 4개짜리 기계적 작업이다.

`Customer`·`Counter`는 데이터 홀더(class, 필드 3~4개). `ShopState`는 `ShopSim` 내부 상태를 묶은 것으로 외부에 노출하지 않는다(저장 모델은 11에서 `ShopSim`이 스냅샷을 내보내는 형태로 정한다).

### 2.3 틱과 수입

- 규칙 틱은 지금처럼 **1초**(`game_config.income.tickSeconds`). `GameManager.Update`가 `IncomeService.Tick`과 `ShopSim.Tick`을 같은 틱에 부른다. 처리 시간이 1.6초 같은 소수여도 `remaining` 누적으로 맞으므로 프레임 틱이 필요 없다. 러시 타이머 표시는 1초 단위로 줄어든다.
- 빵집 수입은 손님당 이벤트라 `IncomePerSecond`(동물 수입)와 별개다. 08에서는 상단 바의 `초당 n`을 그대로 두고, 동물 수입은 웜뱃 1마리분이 계속 들어온다. 삭제는 재미 판정 뒤 정리 단계에서.
- 코인은 `ZooState.AddCoins` 한 곳. `CustomerServed` 이벤트의 금액은 팝업 표시용이고, 지급은 `ShopSim` 안에서 끝난다.

### 2.4 Game

- `GameManager.Init`: `Rule = new BakeryRule(Tables.Config.Shop)` → `Shop = new ShopSim(State, Facility, Tables, Rule, new SystemRandom())` → `Navigation = new Navigation()`. 공개 프로퍼티 `Shop`·`Navigation`.
- `GameManager.Update`: 틱마다 `Income.Tick(dt); Shop.Tick(dt);`.
- `MainScene.Awake`: `UIManager.Open<ShopHudView>()` → `new ShopHudPresenter(view, shop, navigation, tables.Strings)`. 가차 버튼·결과 카드는 열지 않는다(코드는 남김). `WorldManager.Instance.Initialize(state, tables, shop, navigation)`.

### 2.5 World

- **`Unit` 수정**: `Setup(record, frames, Func<Vector2, Vector3> toScreen)`. `SetLogical`이 이 변환을 쓴다. 지상 개체는 `Iso.ToScreen`, 내부 개체는 `v => new Vector3(v.x, v.y, 0)`. 걷기(`StepTowards`)·상태 객체·프레임은 그대로. 이 한 줄 주입으로 `Customer`가 두 화면 어디서든 같은 클래스다.
- `ShopView`(프리팹 `Prefabs/Shop.prefab`, 루트 (1000, 0)): 더미 스프라이트 — 바닥·문·카운터 3·오븐(단색, Pillow). 자식 Transform으로 `QueueCells[10]`·`CounterSpots[3]`·`Door`·`WombatSpot`. 좌표는 1.1 표. 화면 y 정렬(기존 Custom Axis)은 그대로 통한다.
- `Visitor` → `Customer`, `VisitorSpawner` → `CustomerSpawner` (.meta 유지 개명). 관광객 수 = f(수입) 로직과 `TargetCount`는 삭제. 스포너는 `ShopView` 자식이고 `ShopSim.CustomerArrived`를 받아 개체를 문 위치에 만들고 `Dictionary<int customerId, Customer>`로 시뮬 손님과 개체를 잇는다.
- `Customer` 상태 흐름: 문 → `WalkState`(자기 줄 칸) → `WaitState` → `QueueChanged`마다 칸 갱신(한 칸 앞으로 걷기 = `WalkState` 재진입) → `CustomerServing` → 카운터 자리 → `CustomerServed` → 코인 팝업(기존 `CoinPopup`) → `WalkState`(문) → 화면 밖 파괴. `CustomerLeft`면 바로 문으로.
- `Wombat : Unit`: `WombatSpot` 고정. `SlamStarted`에 0.3초 스쿼시(코드), 아트는 나중. 기존 `Animal`·`SyncAnimals`는 08에서 안 부른다.
- `WorldManager`: `Update`에서 탭 판정(드래그가 아닌 짧은 터치, UI 위 시작 제외 — `WorldCameraController`의 판정 재사용) → `Iso.ToLogical(ScreenToWorldPoint)`가 존 사각형 안이면 `navigation.EnterShop()`. `Navigation.Changed` → `Shop`이면 `camera.EnterShop(shopView.Center)`, 아니면 `camera.ExitShop()`.
- `WorldCameraController`: `EnterShop(Vector3 center)`(초점을 center로, 드래그 잠금, 클램프 무시) / `ExitShop()`(직전 초점 복귀, 드래그 해제).
- 지상: `ZoneView`·`BranchView`·타일·숲 그대로. 관광객의 길 가로지르기 로직은 `Customer`로 대체되어 삭제.

### 2.6 UI

- `ShopHudView`(Resources/UI 프리팹): 왼쪽 위 **뒤로**, 상단 바 아래 **줄 게이지 10칸**(찬 칸 색, 8칸 이상 경고색), 러시 종 버튼(평시) ↔ 남은 시간(러시 중), **쿵 버튼**(쿨다운 표시), **카운터 버튼 1·2·3**, 통과/실패 토스트(1.5초). 지상에서는 통째로 숨김.
- `ShopHudPresenter`: `Navigation.Changed`→표시/숨김, `QueueChanged`→게이지, `RushStarted/Ended`→버튼·토스트, `SlamStarted`→쿨다운, 틱마다 남은 시간. 버튼 → `shop.TryStartRush()/TrySlam()/TryServe(i)`, 뒤로 → `navigation.ExitShop()`.
- 꾸미기 버튼(기존 `FacilityButtonView`)은 내부에서만 보이게 같은 Presenter 규칙으로 표시/숨김(한 줄).
