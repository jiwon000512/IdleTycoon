# 설계 03 — 월드 슬라이스

상태: 구현 완료 · 사용자 QA 대기 · 2026-09-14
기능: uGUI 우리 격자를 버리고 2D 월드 맵으로 바꾼다. 우리 하나가 화면을 채우고, 뽑은 동물이 우리 안을 자유롭게 돌아다니며, 중복은 한 마리 더 나타난다. 화면을 드래그해 맵을 팬한다(경계 클램프).
기획서 대응: v0.9 2장(배치·중복·화면), 4장 월드, 6.2 마리 수, 8장 구현 메모
다음 기능: 04 수입 틱(초당 적립, 버튼 남은 시간)

## 0. 결정

### 0.1 사용자 확정 (2026-09-14)

| # | 결정 | 이유 |
|---|---|---|
| D1 | 월드 코드는 **별도 asmdef `ZooTycoon.World`**. 의존 `Game → World → Core` (UI와 같은 층, UI↔World 상호 참조 없음) | Game을 얇은 조립 루트로 유지. 월드 프리팹·이동 코드가 UI와 섞이지 않음 |
| D2 | 동물 이동 연출값(걷기 속도·멈춤 시간·목적지 거리)은 **동물 프리팹 인스펙터** | 기획서에 없는 순수 연출 숫자. `GachaResultView.m_displaySeconds`와 같은 방식 |
| D3 | 카메라는 **드래그 팬만**. 핀치 줌은 이후 | 첫 슬라이스 범위 최소화 |
| D4 | 첫 맵 = **우리 + 주변 여백, 팬 가능**(경계에서 멈춤) | 우리가 하나뿐이어도 팬을 검증할 수 있어야 한다 |

### 0.2 설계 제안 (검토 필요)

| # | 제안 | 이유 |
|---|---|---|
| P1 | **월드 좌표 100px = 1유닛.** 카메라 orthographic size 9.6 → 화면 10.8 × 19.2 유닛 | 1080×1920 기준 해상도와 1:1이라 HUD 픽셀과 월드 유닛 환산이 쉽다 |
| P2 | 우리 이동 영역(동물이 걸을 수 있는 Rect) = x ±4.4, y −4.6 ~ +6.8 (8.8 × 11.4). 울타리 스프라이트는 그 바깥 0.4유닛. 상단 바(1.6유닛)와 가차 버튼 영역(하단 4.2유닛) 아래에 가리지 않는 위치 | "우리 하나가 화면을 채운다"를 HUD에 가리지 않게 만족 |
| P3 | 카메라 중심 허용 범위 = x ±5.4, y ±6 (`CameraPanController.m_bounds`, 인스펙터) | 사방으로 반 화면쯤 잔디 여백이 보이고 멈춘다(D4). 06에서 맵이 넓어지면 이 값만 키운다 |
| P4 | 동물 개체 이동: 영역 안 랜덤 점을 고르고 그리로 직진 → 도착하면 랜덤 시간 대기 → 반복. 좌우 방향에 따라 `flipX`. 길찾기·충돌 없음 | 기획서 8장. 우리 안이 빈 땅이라 직진으로 충분 |
| P5 | 깊이: `SpriteRenderer.sortingOrder = −y × 100` 매 프레임 갱신 | 아래쪽(가까운) 동물이 위에 그려진다. 관광객(05)도 같은 규칙 |
| P6 | **연출 난수는 `UnityEngine.Random` 허용**(월드 계층). 프로그래밍-규약 5장에 예외 명시 | 이동 목적지·대기 시간은 게임 규칙이 아니라 결정성이 필요 없다. `IRandom` 주입은 가차에만 |
| P7 | `WorldPresenter`는 `ZooState.AnimalsChanged`마다 **보유 종별로 마리 수만큼 개체가 있도록 맞춘다**(부족분 스폰). 뽑기 이벤트를 직접 듣지 않는다 | 08 저장·로드 시 상태만 복원하면 월드가 따라온다. 뽑기 결과와 월드가 어긋날 여지가 없다 |
| P8 | **Core 단순화**: 우리 하나·대기실 없음이므로 `ZooState.WaitingRoom`·`AnimalPlacement`·`PullOutcome.Waiting`·`ZooLevelService.UnlockLevelOfCage` 삭제. `AddAnimal(id)`(인자 없음), `PlacedAnimals` → `OwnedAnimals`. `GachaService` 생성자에서 `ZooLevelService` 제거(3개) | 죽은 코드를 남기지 않는다. 우리 해금(06)에서 필요한 형태로 다시 넣는다 |
| P9 | `game_config.cageGrid` 삭제 → **`game_config` version 2**. 검증기의 "마지막 cageCount == 격자 칸 수" 규칙 삭제. `zoo_levels.cageCount`는 데이터·단조 증가 검증만 남기고 **06까지 미사용**(현재 값 3~9는 06에서 재정의) | 격자가 사라져 의미가 없어졌다. 데이터-테이블-규칙 6장 절차대로 스키마 표·레코드·버전을 함께 고친다 |
| P10 | `OwnedAnimal.Level` 이름은 유지(기획서 6.2 "Level = 마리 수"). 문구만 `{0}마리`로 | 수식·테스트가 그대로다. 이름을 바꾸면 이득 없이 diff만 커진다 |
| P11 | 뽑기 결과 카드는 유지. 제목: 새 종 `새 동물!`, 중복 `한 마리 더! {n}마리`. 상세 `등급 · 초당 n`(그 종 전체 수입) | 우리 안에 동물이 나타나는 것이 주 연출이고 카드는 보조. 02 코드 재사용 |
| P12 | 카메라 팬은 `UnityEngine.InputSystem.Pointer.current`를 `Update`에서 폴링. 누르는 순간 `EventSystem.current.IsPointerOverGameObject()`면 드래그 시작 안 함 | 액션 에셋을 만들 만큼의 입력이 아니다. 프로그래밍-규약 9장 "Update는 입력 폴링·표시 보간만"에 해당 |
| P13 | 동물 개체는 `Instantiate`, 풀링 없음 | 개체는 늘기만 하고 없어지지 않는다. `PoolManager`는 관광객(05)에서 검토 |
| P14 | 스프라이트 로드는 `WorldPresenter`가 `Resources.Load<Sprite>(record.Sprite)` 직접 호출(UI의 `AnimalVisuals`와 한 줄 중복) | World가 UI를 참조할 수 없다. 한 줄을 위해 공용 asmdef를 만들지 않는다 |

`AnimalActor.Update` 흐름:

```
대기 중이면 남은 시간 감소, 0이 되면 목적지 = cage.RandomWalkPoint()
이동 중이면 MoveTowards(speed × dt), flipX = 목적지가 왼쪽
도착하면 대기 시간 = Random(idleMin, idleMax)
sortingOrder = -(int)(y × 100)
```

### 1.6 규칙 적용과 예외

- 이벤트 핸들러 `State_AnimalsChanged`. Presenter는 `Dispose`에서 해제.
- 예외: `AddAnimal` 중복, `LevelUpAnimal` 미보유(기존). 월드 계층은 예외를 던지지 않는다.
- **규칙 예외 4(신규)**: 월드 연출에 `UnityEngine.Random` 사용(P6). 프로그래밍-규약 5장 난수 행을 "Core는 `IRandom`. 연출(World)은 `UnityEngine.Random` 허용"으로 고친다.
- `[SerializeField]` 빈 값 검사 없음(설계 01 예외 3).

## 6. 원근 카메라로 전환 (2026-09-14, 사용자 스크린샷 후)

### 6.1 문제 특정

우리 단위 원근(5장 A1·A4)은 우리를 **세로로 쌓으면** 위 우리의 앞 변(폭 100%)이 아래 우리의 뒤 변(폭 75%) 위에 놓여, 위 우리가 더 가까워 보인다. 우리마다 소실점이 따로라 인접한 원근 단서가 모순된다. 조정값으로 풀리지 않는 구조적 문제.

### 6.2 결정

| # | 결정 | 이유 |
|---|---|---|
| A5 | **원근 카메라(3D perspective)로 전환.** 월드는 XZ 평면(y = 0), 카메라는 55° 내려다봄, FOV 60. 우리는 **사각형**으로 복귀, 동물은 카메라를 향해 세운 카드(빌보드, 피벗 발), 그림자는 땅에 눕힌 스프라이트. 5장의 사다리꼴·`m_backScale`·수동 정렬 삭제 | 화면 전체에 소실점이 하나라 우리를 몇 개 쌓아도 모순이 없다. 원근·정렬을 코드로 흉내 낼 필요가 없어 World가 오히려 단순해진다. Core·UI·가차 영향 없음 |
| A6 | 카메라는 **초점(XZ 한 점)** 으로 제어: 위치 = 초점 − forward × 거리. 팬 = 포인터를 y=0 평면에 레이캐스트한 이동량만큼 초점 이동, 범위는 XZ Rect | 줌(이후)은 거리만 바꾸면 된다. 팬 범위 계산(A3)은 그대로 |
| A7 | 깊이 정렬은 카메라 **거리 정렬**(URP 2D Renderer, Transparency Sort Mode = Default → 원근 카메라에서 거리). 땅 −1000, 그림자 −900, 잔디 −2000만 고정 | `sortingOrder = −y×100` 같은 수동 정렬이 필요 없다 |
| A8 | 시작 프레이밍: 초점 (0, −2.2), 거리 17 → 가운데 우리가 화면 세로 0.32~0.79(HUD 사이), 가로 꽉 참. 에이전트가 에디터 카메라 렌더로 확인 | 플레이 모드 없이 `capture_game_view --source camera`로 검증 가능 |
