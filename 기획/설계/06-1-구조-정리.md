## 2. 월드 개체 구조 (5)

```
Unit (abstract MonoBehaviour)            공통 몸체: ModelRoot·Sprite·Shadow·SpriteAnimator 직렬화 필드(프리팹 데이터 유지)
  Setup(IUnitRecord, FrameCache, billboard)   크기·빌보드·그림자·프레임(idle/move)·속도
  ChangeState(UnitState)                   Update는 m_state.Update(dt) 한 줄
  PlayIdle / PlayMove / Face(x) / StepTowards(target, dt) → 도착 여부   상태 객체가 쓰는 동작
├─ Animal   : WaitState(idle 시간) ⇄ WalkState(우리 안 임의 지점)
└─ Visitor  : WalkState(입장) → WaitState(구경, 코인 팝업) → WalkState(퇴장) → Exited. 동물 없는 우리면 입장 걸음이 바로 퇴장
UnitState (abstract): Enter(), Update(dt)
├─ WalkState(unit, arrived) : SetTarget → Enter에서 Face+PlayMove, 도착하면 arrived()
└─ WaitState(unit, done)    : SetSeconds → Enter에서 PlayIdle, 시간이 다 되면 done()
```

- `IUnitRecord`(Core): `AnimalRecord`·`VisitorRecord` 공통 연출 칼럼 6개. `Unit.Setup`이 이것만 본다.
- 이름 규칙(코드-규칙 5장): 개체는 접미사 없는 명사, `...Actor` 금지. 상태는 `...State`. 전이는 `Enter...` 메서드가 `SetTarget/SetSeconds` 후 `ChangeState`.
- 상태 인스턴스는 `Initialize`에서 한 번 만들어 재사용(전이마다 할당 없음).
- `AnimalState`·`VisitorState` enum 삭제. 프리팹 `Animal.prefab`·`Visitor.prefab`(GUID 유지, 루트 이름 변경). `CageView.AnimalCount`가 우리별 동물 수를 가져 `WorldView.m_animalCounts` 배열 삭제. `VisitorSpawner`는 `WorldView.Visitors`로 노출해 `MainScene`·`WorldPresenter`가 스포너를 따로 받지 않는다.
