# 설계 06 — 관광객

상태: 구현 완료 · 2026-09-14
기능: 관광객이 우리 앞 길을 걷고, 동물이 있는 우리 앞에 멈춰 구경하면 머리 위에 코인이 뜬다. 관광객 수는 초당 수입에서 계산한다(D1). 수입 자체는 관광객과 무관(기획서 2장).
기획서 대응: 2장 관광객·성장 축(시설은 관광객 수 × 단가), 4장 월드 표 관광객, 6.4 홍보 "단계마다 관광객 +1", 8장 구현 메모
다음 기능: 07 동물원 레벨업과 우리 해금·맵 확장

---

## 0. 결정

### 0.1 사용자 확정 (2026-09-14)

| # | 결정 | 이유 |
|---|---|---|
| D1 | **관광객은 보여주기용이고, 수는 획득 가능한 코인(초당 수입)에 따라 정한다.** 제안했던 "기본 3 + 홍보 단계 × 1"은 기각 | 사용자 답변. 홍보·별·시설 무엇이든 수입을 올리면 관광객이 따라 늘어 성장 축 3개 전부의 피드백이 된다. 수식은 P1 |
| D2 | 길 모델은 **우리 앞 띠**. 우리마다 앞(−Z)에 길 타일 한 줄, 관광객은 한쪽 끝에서 나타나 가로질러 반대쪽으로 나간다. 길찾기 없음 | 07의 격자 배치에도 우리마다 띠 하나로 확장 |
| D3 | 코인 연출은 **머리 위 떠오르기만**. 바닥 코인 줍기(9.1 B2)는 별도 기능 | 기획서 4장 범위 유지 |

### 0.2 설계 제안

| # | 제안 | 이유 |
|---|---|---|
| P1 | 관광객 수는 **Core `VisitorCalculator.Count(incomePerSecond, config.Visitors)`**: 수입 0 → 0, 그 외 min(`maxCount` 12, 1 + ⌊log₂(1 + 수입 ÷ `incomeUnit` 1)⌋). 웜뱃 1마리 2명, 3/초 3명, 7/초 4명, 약 2,000/초부터 12명 | D1. 선형이면 몇 십 코인에서 상한에 닿고, 로그면 게임 전체 구간에서 천천히 는다. `promotion.visitorsPerStage`는 삭제(홍보는 수입을 통해 간접 반영). 시설(C3)이 이 수를 쓸 때는 동물 수입 기준이라 순환이 없다 |
| P2 | 관광객 종류는 **새 테이블 `visitors.json`**(version 1): `id, name, sprite, idleSheet, moveSheet, frameRate, scale, moveSpeed, viewSecondsMin, viewSecondsMax, weight, sortOrder`. 스폰마다 가중치로 한 종류를 고른다. 첫 행은 더미 실루엣 1개 | animals와 같은 방식. 실제 아트(여러 실루엣·색)가 오면 행만 늘린다. 프리팹·코드에 숫자 0개 |
| P3 | 생애 주기 FSM `VisitorState { Enter, View, Leave }`. Enter: 띠 끝에서 구경 지점 X까지 걷기 → View: 멈춰 우리를 향하고(`flipX`) 코인 팝업, `viewSeconds` 대기 → Leave: 반대 끝까지 걷기 → 파괴. 진행 방향은 스폰마다 랜덤(좌→우 / 우→좌) | 05의 `AnimalActor`와 같은 enum + Enter 메서드 패턴. `SpriteAnimator` 재사용 |
| P4 | 구경은 **동물이 있는 우리에서만**. 목표 우리는 동물이 있는 우리 중 랜덤, 하나도 없으면 아무 우리의 띠를 멈추지 않고 지나간다(코인 없음) | 빈 우리를 구경하는 게 어색하다. 게임 시작 직후엔 지나가기만 하다가 첫 뽑기 뒤 멈춰서 코인이 뜨는 것이 자연스러운 첫 피드백 |
| P5 | 길 띠의 기하는 **`CageView`의 `Path` 자식 SpriteRenderer(눕힌 타일) 경계**에서 읽는다(`CageView.PathBounds`, XZ). 스폰 X = 경계 xMin − 1.5, 퇴장 X = xMax + 1.5, Z는 경계 안 랜덤 | 길 타일이 보이는 곳이 곧 걷는 곳. 숫자를 따로 두지 않는다. 07에서 우리 프리팹을 만들면 함께 옮긴다 |
| P6 | 개체 수 유지는 `VisitorSpawner : MonoBehaviour`(World, `World` 오브젝트). `TargetCount` 설정, `Update`에서 `alive < TargetCount`면 스폰 간격(`m_spawnInterval`, 인스펙터 1.5초)마다 1명 스폰. 관광객 퇴장은 `VisitorActor.Exited` 이벤트로 감지 | 한 번에 N명이 같은 위치에 튀어나오지 않게 간격을 둔다. 간격은 기획서에 없는 순수 연출 숫자라 인스펙터(설계 03 D2) |
| P7 | `Instantiate`/`Destroy`, 풀링 없음 | 최대 13명, 몇 초에 하나. GameKit `PoolManager`는 Game·UI 계층 전용이고(프로그래밍-규약 10장) 이 규모에 풀은 과잉이다 |
| P8 | 코인 팝업은 `CoinPopup` 프리팹(World): 빌보드 스프라이트가 `m_riseHeight`(0.8) 만큼 `m_seconds`(0.7) 동안 올라가며 투명해진 뒤 자기 파괴. 관광객 머리 위(스프라이트 높이)에서 시작 | 연출 숫자는 프리팹 인스펙터. 08 이후 B2로 바꿀 때 이 프리팹만 교체 |

| P10 | `WorldView`는 우리별 동물 수를 센다(`SpawnAnimal`에서 +1). `VisitorSpawner`가 `WorldView.CagesWithAnimals()`로 목표 우리를 고른다 | P4. 상태(`ZooState`)는 우리 배정을 모르므로 World가 센다 |

| P12 | 깊이 정렬은 기존 카메라 거리 정렬. `Path` order −1500(잔디 −2000과 땅 −1000 사이) | 설계 03 A7 |

### 1.3 상태 흐름 (`VisitorActor`)

```
Initialize(cage, view) : 방향 = 랜덤. 시작 = (xMin−1.5 또는 xMax+1.5, z 랜덤 in PathBounds). 끝 = 반대쪽
                         구경 X = Random(xMin+1, xMax−1) → EnterWalk(Enter, views ? 구경점 : 끝)
Enter : MoveTowards(구경점 또는 끝, moveSpeed); Play(move); flipX = 진행 방향 왼쪽
        구경점 도착 → EnterView / 끝 도착 → 퇴장
View  : Play(idle); flipX = 우리 중심이 왼쪽; CoinPopup 생성(머리 위); timer = Random(viewMin, viewMax)
        timer 0 → EnterLeave
Leave : MoveTowards(끝); Play(move); 도착 → Exited 발생, Destroy
```

`CoinPopup.Update`: y += riseHeight × dt / seconds, α = 1 − t/seconds, t ≥ seconds → Destroy.

### 1.6 규칙 적용과 예외

- 핸들러 이름 `Visitor_Exited`. Spawner는 `OnDestroy`에서 남은 관광객 이벤트 해제 불필요(관광객이 먼저 파괴되거나 씬과 함께 사라짐).
- 연출 난수는 `UnityEngine.Random`(규약 예외, World). 관광객 종류 가중 선택도 연출이므로 World에서 `Random.value`.
- Core·Data `UnityEngine` 0건. 한국어 리터럴 0건(문구 없음).
- 종 → 우리 배정은 03 A2의 임시 규칙(보유 순서 % 우리 수) 유지. 07에서 확정.

## 3. 구현 결과 (2026-09-14)

| # | 달라진 점 | 이유 |
|---|---|---|
| C1 | D1이 제안과 달라 관광객 수를 홍보 단계가 아니라 **초당 수입의 로그**로 계산(P1). `promotion.visitorsPerStage` 삭제, `game_config.visitors` 신설 | 사용자 결정 |
| C2 | P4의 "동물이 없으면 지나가기만"은 수입 0 → 관광객 0이라 시작 직후엔 일어나지 않는다. 우리 선택 규칙(동물 있는 우리 우선)은 그대로 | D1의 결과. 코드 단순화는 하지 않음(우리가 여러 개일 때 빈 우리를 피하는 데 여전히 쓰임) |
| C3 | 씬 스크립트에서 `GetComponent<T>() ?? AddComponent` 가 Unity 가짜 null 때문에 실패 → `TryGetComponent`로. 이미 열린 씬은 다시 열지 않음(더티 씬 재오픈 대화상자 방지) | 에디터 스크립트 요령. 진행상황에 기록 |
| C4 | `VisitorActor`에 `using System`(이벤트)과 `UnityEngine.Random`이 충돌 → `using Random = UnityEngine.Random` | 컴파일 오류 1회 |
| C5 | **버그 수정(사용자 지적)**: 우리 가운데에서 옆으로 떨어진 관광객이 앞 난간 뒤에 그려졌다. 원인은 카메라 거리 정렬(03 A7): 난간은 9.6유닛 한 장이라 정렬점이 가운데 하나뿐이고, 관광객 x가 멀수록 카메라 거리가 늘어 난간(z −6.1)보다 0.4유닛 앞(z −6.5)에 있어도 "더 멀다"로 판정. 정렬점을 Pivot으로 바꾸는 것만으로는 부족했고(가운데 관광객만 해결), **URP 2D Renderer의 Transparency Sort Mode를 Custom Axis (0,0,1)** 로 바꿔 Z만으로 앞뒤를 정하게 했다. 동물·관광객 `Sprite`와 난간 12개는 Sort Point = Pivot. 확대 캡처로 화면 양끝의 관광객이 난간 앞에 그려짐을 확인 | 원근 카메라라도 월드는 평면이라 깊이 = Z. 거리 정렬은 넓은 스프라이트에 맞지 않는다 |
