# 설계 01 — 부트스트랩과 상단 바

상태: 구현 완료 · 2026-09-14
기능: 앱을 켜면 테이블을 읽고 검증한 뒤 새 게임 상태(코인 300)를 만들고, 상단 바에 코인·초당 수입·동물원 레벨과 진행도를 표시한다. 이후 모든 기능이 올라탈 뼈대.
기획서 대응: 4장 상단 바, 6.4 시작 상태, 데이터-테이블-규칙 7장·8.5
다음 기능: 02 가차(버튼·추첨·우리 격자·더미 스프라이트)

---

## 0. 확정 결정 (2026-09-14)

| # | 결정 | 이유 |
|---|---|---|
| D1 | 레코드·`GameTables`는 **Core**, `TableValidator`만 **Data** | Core 서비스가 레코드를 직접 읽어야 하는데 Core는 Data를 참조할 수 없다. asmdef 6개는 유지 |
| D2 | 봉투(`table`·`version`) 검증은 **EditMode 테스트에서만** | GameKit `TableManager.Load<TRow>()`가 `Rows`만 돌려주고 봉투를 버린다. GameKit은 건드리지 않는다 |
| D3 | UI 문구는 **`strings.json`** 에서 온다. 코드·프리팹에 한국어 리터럴 금지 | 문구를 한 곳에서 고치기 위함. 다국어는 아직 범위 밖이라 `ko` 칸 하나만 둔다 |
| D4 | 문구 조회는 **Core `StringTable` + 생성자 주입** | 코드-규칙(싱글턴 금지·생성자 주입)과 그대로 맞고 GameKit 수정이 없다 |
| D5 | 상단 바는 **값 3개 + 진행도 숫자** (`300` / `초당 0` / `Lv.1` / `0/2,000`) | 기획서 4장의 "레벨과 진행도"를 더미 아트 없이 충족 |
| D6 | 문구 키는 밑줄 표기(`topbar_coins`) | 데이터-테이블-규칙 4장 ID 패턴 `^[a-z][a-z0-9_]*$`를 고치지 않기 위함 |
| D7 | 스프라이트 **파일 존재** 검증은 02로 미룬다 | 더미 스프라이트가 아직 없어 지금 넣으면 반드시 실패한다. 이번엔 `sprite`가 비어 있지 않은지까지만 |
| D8 | `ZooState`가 `AddCoins`/`TrySpendCoins`를 직접 갖는다 | 코인은 수입·가차·홍보 셋이 건드리므로 모델이 단일 출처. 구현 후 코드-규칙 3장 문구를 "모델 또는 서비스의 메서드로만"으로 고친다 |
| D9 | Presenter는 생성 직후 1회 초기 갱신 | 이벤트만 구독하면 첫 프레임이 빈 값이 된다 |

## 1. 코드 설계

### 1.1 계층 조정 (D1)

```
UI ──▶ Game ──▶ Data ──▶ Core        UI·Game ──▶ Core,  Game·UI ──▶ GameKit
```

| asmdef | 이번 세션에 바뀌는 것 |
|---|---|
| `ZooTycoon.Core` | 변경 없음(`references: []`, `noEngineReferences`). 레코드는 Newtonsoft 속성을 쓰지 않으므로 참조가 필요 없다 |
| `ZooTycoon.Data` | 변경 없음 |
| `ZooTycoon.Game` | `GameKit.Core`, `GameKit.Unity` 참조 추가 — 코드-규칙 2장 표에 이미 있는 값으로 맞추는 것 |
| `ZooTycoon.UI` | `GameKit.Core`, `GameKit.Unity` 참조 추가 — 위와 같음 |
| `ZooTycoon.Tests.EditMode` | `GameKit.Core` 참조와 `Newtonsoft.Json.dll` 추가 — **코드-규칙 2장 표에 없는 변경**. Q2가 실제 JSON을 `TableFile<T>`로 읽어야 해서 필요하다 |

### 1.2 클래스

| # | 계층 · 폴더 | 클래스 | 책임 | 의존 |
|---|---|---|---|---|
| 1 | Core/Tables | `AnimalRecord`, `GradeRecord`, `ZooLevelRecord`, `StringRecord` | JSON 행과 1:1 DTO | 없음 |
| 2 | Core/Tables | `GameConfig` (중첩 `StartConfig`·`CageGridConfig`·`GachaConfig`·`AnimalLevelConfig`·`PromotionConfig`·`OfflineConfig`) | `game_config.json`과 1:1 | 없음 |
| 3 | Core/Tables | `GameTables` | 다섯 테이블 보관·조회: `Animals`, `Grades`, `ZooLevels`, `StringRows`, `Strings`(StringTable), `Config`, `GetAnimal(id)`, `GetGrade(id)` | 1, 2, 4 |
| 4 | Core/Tables | `StringTable` | `Get(id)`, `Format(id, args)`. 없는 키는 예외(버그) | 1 |
| 5 | Core | `ZooState` | 상태 소유. `Coins`, `TotalCoinsEarned`, `PullCount`, `PromotionStage`, `PlacedAnimals`, `WaitingRoom`, `LastSavedAtUtc`. 이번에는 `CreateNew(config)`, `AddCoins`, `TrySpendCoins`만. 이벤트 `CoinsChanged(double)` | 2 |
| 6 | Core | `PlacedAnimal` | 우리 한 칸: `AnimalId`, `Level`. 배치·레벨업은 02 | 없음 |
| 7 | Core | `ZooLevelService` | `Level`, `CageCount`, `NextThreshold`(마지막 레벨이면 null), `IsPromotionUnlocked`, `Refresh()`. 이벤트 `ZooLevelReached(int)`. 대기실 입장은 02 | 3, 5 |
| 8 | Core | `IncomeCalculator`(static) | `AnimalIncome(baseIncome, level, bonusPerLevel)`, `TotalIncomePerSecond(state, tables, promotionMultiplier)` | 2, 3, 5 |
| 9 | Data | `TableValidator`(static) | `IReadOnlyList<string> Validate(GameTables)` — 데이터-테이블-규칙 7장(봉투 제외, D2) | 3 |
| 10 | Game | `GameBootstrap`(MonoBehaviour, 씬에 1개) | `Awake`: `TableManager`로 5개 테이블 로드 → `GameTables` → `TableValidator`(오류 있으면 예외로 중단) → `ZooState.CreateNew` → `ZooLevelService` → `UIManager.Open<TopBarView>()` → `TopBarPresenter`. `OnDestroy`에서 Presenter `Dispose` | 3, 5, 7, GameKit |
| 11 | UI | `TopBarView : UIView` | `[SerializeField]` TMP 텍스트 4개(코인·수입·레벨·진행도). `SetCoins/SetIncome/SetZooLevel/SetProgress(string)` | GameKit.UI, TMP |

의존 방향: UI → Game → Data → Core. Presenter는 구현이 하나뿐이므로 View 인터페이스를 만들지 않고 View 클래스를 직접 받는다.

### 1.3 문구 테이블 (D3·D5·D6)

새 파일 `Assets/Resources/Data/strings.json` (`table: "strings"`, `version: 1`). 이번 세션의 행:

| id | ko |
|---|---|
| `topbar_coins` | `{0}` |
| `topbar_income` | `초당 {0}` |
| `topbar_level` | `Lv.{0}` |
| `topbar_progress` | `{0}/{1}` |
| `topbar_progress_max` | `MAX` |

- 서식은 `string.Format` 플레이스홀더. 코인·수입은 `BigNumberFormatter`로 먼저 문자열을 만든 뒤 끼워 넣는다.
- 진행도는 `누적 획득 코인 / 다음 레벨 기준`을 천 단위 쉼표(`N0`)로 적는다. 마지막 레벨이면 `topbar_progress_max`.
- 프리팹의 TMP에 박힌 초기 텍스트는 플레이스홀더이며 런타임에 전부 덮어쓴다.

### 1.4 씬·프리팹·리소스 (CLI로 생성)

| 대상 | 내용 |
|---|---|
| `Main.unity` | `GameBootstrap` 빈 오브젝트 1개, `EventSystem`(+`InputSystemUIInputModule`) 1개. **Canvas는 넣지 않는다** — `UIManager`가 런타임에 1080×1920 ScaleWithScreenSize Canvas를 직접 만든다 |
| `Resources/UI/TopBarView.prefab` | 상단 고정 패널 1080×160. 좌: 코인, 중: 초당 수입, 우: `Lv.n`과 진행도 2줄. 더미 배경색, TMP 기본 폰트 |
| 더미 리소스 | 이번 세션에는 없음(동물 스프라이트는 02) |

### 1.5 규칙 적용과 예외

- Core·Data는 UnityEngine 없음. 숫자는 전부 테이블에서. 주석은 기획서 표 번호와 규칙 예외에만.
- 이벤트 핸들러 이름 `State_CoinsChanged`, `ZooLevelService_ZooLevelReached`. Presenter는 `Dispose`에서 해제.
- 예외는 테이블 검증 실패(부트스트랩 중단), 없는 ID 조회, 없는 문구 키에만. 검증기 자체는 예외를 던지지 않고 오류 목록을 돌려준다(프로그래밍-규약 6장).
- **규칙 예외 1**: 레코드가 `get/set`이다. 프로그래밍-규약 5장은 불변을 요구하지만 Newtonsoft 역직렬화에 setter가 필요하고, `init`은 netstandard 2.1에서 `IsExternalInit`이 없어 쓸 수 없다. 각 레코드 파일에 주석을 남긴다.
- **규칙 예외 2**: `GameTables` 생성자 매개변수 5개. 코드-규칙 3장의 상한이다. 테이블 집합체라 분리할 축이 없다.
- **규칙 예외 3**: `[SerializeField]` 빈 값 검사를 넣지 않는다. 프로그래밍-규약 9장은 요구하지만 1장(v1.1) "요청되지 않은 방어 장치를 넣지 않는다"를 우선한다.

### 4.3 규칙 예외 (코드에 주석으로 남김)

1. 레코드 5종의 `get/set` — Newtonsoft 역직렬화. `init`은 netstandard 2.1에서 불가.
2. `GameTables` 생성자 매개변수 5개 — 테이블 집합체라 나눌 축이 없다.
3. `[SerializeField]` 빈 값 검사를 넣지 않음 — 프로그래밍-규약 1장(v1.1) "요청되지 않은 방어 장치를 넣지 않는다"를 9장보다 우선.
4. `GameBootstrap`의 한국어 예외 메시지 — 프로그래밍-규약 6장이 예외 메시지를 한국어로 요구하므로 UI 문구 규칙(D3)의 대상이 아니다.
