# 설계 07-1 — 시점 전환 (직교 + 쿼터뷰)

상태: 구현 완료 · 2026-09-16 · **같은 날 07-2(순수 2D)로 대체됨.** 원근 폐기 결정(D1)만 살아 있다
기능: 원근 카메라(FOV 60, 55° 정면 부감)를 직교 카메라 + 쿼터뷰(Y 45°, 35° 내려다봄)로 바꾼다. 월드가 XZ 평면 위의 스프라이트 카드라 카메라 설정과 정렬 축만 바뀌고 아트는 그대로다.
기획서 대응: 2장 시점, 4장 카메라·시점, 8장 아트 파이프라인 (v0.18)
다음 기능: 08 존·입주·번식

---

## 0. 결정

### 0.1 사용자 확정 (2026-09-15)

| # | 결정 | 이유 |
|---|---|---|
| D1 | **원근 폐기, 직교.** | 웜뱃이 픽셀아트로 바뀐 뒤 원근은 거리마다 픽셀 크기가 달라 픽셀 퍼펙트가 불가능하고, 존이 여럿이면 같은 존이 크기가 달라 보인다 |
| D2 | **쿼터뷰(Y 45°, 35°).** 정면 부감(B)보다 쿼터뷰(C) | 시설·꾸미기가 루프의 핵심(v0.17)이고 레퍼런스(고양이 오피스)가 쿼터뷰. 세운 물체가 두 면으로 보여 "놓았다"가 잘 읽힌다. 같은 씬을 카메라만 바꿔 찍은 세 장(비교 페이지)으로 결정 |
| D3 | 동물·관광객은 정면 카드 + 좌우 반전 그대로 | 고양이 오피스의 고양이도 정면. 2026-09-14의 "쿼터뷰 = 방향별 스프라이트 부담" 기각 사유 철회 |

### 0.2 설계 제안

| # | 제안 | 이유 |
|---|---|---|
| P1 | `WorldCameraController`: `m_yawDegrees`(45) 추가, `BillboardRotation = Euler(tilt, yaw, 0)`, 기본 tilt 35. 카메라 위치 계산은 그대로(초점 − forward × 거리) | 빌보드·시설·코인 팝업이 전부 `BillboardRotation`을 쓰므로 한 곳만 바꾼다 |
| P2 | Main Camera: `orthographic` true, size 8. 원근 FOV는 무시됨 | 마름모 폭이 세로 화면보다 넓어 존 양옆 모서리가 잘리지만 팬으로 본다(고양이 오피스와 같음) |
| P3 | `Renderer2D.asset` 정렬 축 (0,0,1) → **(1,0,1)** | 카메라 진행 방향의 XZ 성분. 멀수록(x+z 큼) 먼저 그린다. 06의 Pivot 정렬점은 그대로 |
| P4 | `Unit.Face(float x)` → **`Face(Vector3 target)`**: `Dot(target − 위치, Billboard × right) < 0`이면 반전 | 쿼터뷰에서 "화면 왼쪽"은 월드 −X가 아니라 카메라 오른쪽 벡터의 반대다. `WalkState`·`Visitor`(우리 중심 `Vector3`) 호출부 수정 |
| P5 | 존 배치·팬 범위·길·이동 영역은 그대로(XZ 사각형). 픽셀 퍼펙트(Pixel Perfect Camera)는 이후 | 카메라만 돌아갔을 뿐 월드 좌표는 변한 게 없다 |
