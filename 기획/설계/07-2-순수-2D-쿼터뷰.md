# 설계 07-2 — 순수 2D 쿼터뷰

상태: 구현 완료 · 2026-09-16
기능: 07-1의 "XZ 평면 + 기울인 3D 카메라 + 빌보드" 구조를 버리고, 장르 표준인 **순수 2D 쿼터뷰**(XY 평면, 2:1, 화면 y 정렬)로 바꾼다. 논리 좌표(XZ)는 그대로 두고 `Iso` 변환 하나가 화면 좌표를 만든다. 눕는 것(바닥·길)은 마름모로 미리 만든 스프라이트, 서 있는 것(울타리·시설·동물)은 쿼터뷰 각도로 그린 스프라이트.
기획서 대응: 2장 시점, 4장 시점, 8장 월드·아트 파이프라인 (v0.19)
다음 기능: 08 존·입주·번식

---

## 0. 결정

### 0.1 사용자 확정 (2026-09-16)

| # | 결정 | 이유 |
|---|---|---|
| D1 | **순수 2D.** 3D 카메라·빌보드·정렬 축 (1,0,1) 폐기 | 원근을 버린 뒤 3D 카메라를 둘 이유가 남지 않았다. 쿼터뷰 모바일 방치형(고양이 오피스 등)은 전부 미리 그린 쿼터뷰 스프라이트를 XY에 놓는 방식이고, 나중에 읽는 사람도 멈추지 않는다. 픽셀아트도 땅까지 1:1 |
| D2 | 리소스는 **더미로 넣고 프롬프트를 사용자에게** 준다(`기획/아트-프롬프트.md` 월드 절) | 사용자 지시 |

### 0.2 설계 제안

| # | 제안 | 이유 |
|---|---|---|
| P1 | **`Iso`**(World, static): `ToScreen(Vector2 논리)` = ((x − z)·kX, (x + z)·kY), `ToLogical`, `ToScreenBounds(Rect)`. kX = 0.7071, kY = 0.3536(2:1, 07-1의 화면 크기와 같음). 논리 +X = 화면 오른쪽 위, +Z = 왼쪽 위 | 두 좌표계를 잇는 유일한 곳 |
| P2 | `Unit`: **`Logical`(Vector2)**이 진짜 위치, `SetLogical`이 `transform.position = Iso.ToScreen`. `StepTowards`·`Face`·`RandomWalkPoint`·길 좌표 전부 논리 Vector2. 빌보드·회전 없음. 그림자는 `localScale.y = kY/kX`인 타원 | 이동·판정 코드는 07 이전과 같고 화면 변환만 한 곳 |
| P3 | `CageView`: 논리 사각형 3개(`m_groundArea`·`m_walkArea`·`m_pathArea`, 로컬) + `m_center`. **바닥·앞길·울타리를 `Awake`에서 세운다**: 바닥·길은 평행사변형 스프라이트 1장을 영역 중심에, 울타리는 한 칸 스프라이트를 네 변에 `m_fenceStep`(0.96) 간격으로(Z변은 `flipX`), 정렬점 Pivot(기둥 밑) | 씬에 손으로 놓을 것이 없고, 08의 존 3개는 컴포넌트 값만 다르다. 긴 울타리 한 장은 y 정렬이 깨지므로 칸 단위(2D 쿼터뷰 표준) |
| P4 | 카메라: 직교, 회전 없음, z −10. 팬은 초점(화면 XY) 이동 + 화면 사각형 클램프. 범위 = `Iso.ToScreenBounds(우리 ∪ 길)` + 여유 | 표준 2D |
| P5 | 정렬: `Renderer2D.asset` 축 **(0,1,0)**(화면 y가 클수록 멀다, 먼저 그림). 바닥 −1000·길 −1500·그림자 −900·잔디 −2000 고정 order는 그대로 | 2D 쿼터뷰 표준 |
| P6 | 더미 리소스(순수 python으로 생성): `Sprites/World/zone_floor.png`(9.6×12.2 평행사변형, PPU 128, 피벗 중앙) · `zone_path.png`(13.6×1.8) · `fence.png`(기둥 + 2:1 가로대 한 칸, 피벗 기둥 밑). `ground.png`·`path.png`(정사각 타일)·`fence_rail.png`(정면 난간)는 더 이상 참조하지 않는다 | 실제 아트는 같은 경로로 교체. 눕는 텍스처는 사용자가 top-down seamless로 만들면 에이전트가 평행사변형으로 변환 |
| P7 | 씬: `Cage`의 자식(Ground·Rail×4·Path) 삭제, `CageView`에 사각형·스프라이트 연결. `Grass`는 XY에 눕힘(회전 0). 카메라 초점 (0, 0) | P3 |
| P8 | 프리팹 `Animal`·`Visitor`·`Facility`·`CoinPopup`: 회전은 코드에서 안 건드리므로 그대로(전부 identity). `Shadow` 로컬 y 0.02 → 0 | 2D에서는 y가 곧 정렬 |
| P9 | `CoinPopup`은 화면 위(+Y)로 떠오른다. `Initialize(billboard)` 삭제 | |

## 3. 구현 결과 (2026-09-16)

- 검증: 컴파일 0 · 콘솔 오류 0 · EditMode **98/98** · 플레이 캡처(웜뱃 3, 입간판·벤치 구매): 마름모 바닥, 칸 울타리, 동물 크기 균일, 입간판이 앞 왼쪽 모서리, 앞 울타리가 동물 앞. 드래그 팬은 자동화하지 않았다(`simulate_pointer` 인자 미확인).
- 달라진 점: 시작 초점을 (0, 0) → (0, −2.5)로 내렸다. 길이 HUD(뽑기·꾸미기 버튼)에 가려서.
- 프리팹 `Shadow`의 로컬 y 0.02는 그대로 두었다(2D에서 2.5px 위, 정렬은 order −900이라 영향 없음). 에디터 스크립트의 `Transform.Find ?? Find`가 Unity 가짜 null로 실패한 것이 원인(진행상황의 요령 그대로).
- `Sprites/World/ground.png`·`path.png`·`fence_rail.png`(사용자 실제 난간)는 참조가 끊겼다. 파일은 남겼고 삭제는 사용자 결정.
