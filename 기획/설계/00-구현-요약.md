# 구현 요약 — 01 ~ 07-5 (2026-09-17 정리)

기능별 설계 문서 12편(01·02·03·04·05·06·06-1·07·07-2·07-3·07-4·07-5)을 지우고 **지금 코드에 살아 있는 결정만** 한 장으로 남긴다. 결정의 경위·QA 표·폐기된 대안은 git 이력(커밋 `6b30668` 이전의 `기획/설계/`)에 있다. 숫자·범위의 단일 출처는 여전히 기획서와 데이터-테이블-규칙, 코드 구조는 코드-규칙이다.

## 1. 계층과 조립

- asmdef 6개, 의존은 `Game → UI → Core`, `Game → World → Core`, `Game → Data → Core`. UI와 World는 서로 모른다. Core·Data는 UnityEngine 없음.
- 레코드·`GameTables`·`StringTable`은 **Core**, `TableValidator`만 Data. 봉투(`table`·`version`) 검증은 EditMode 테스트에서만(GameKit `TableManager`가 봉투를 버린다).
- `GameManager : MonoSingleton`(Game): `Init()`이 테이블 로드·검증(실패 시 예외) → `ZooState` → 서비스 생성. `State != null`이면 즉시 반환(1회 가드). `Update`가 `deltaTime`을 누적해 `income.tickSeconds`(1초)마다 `IncomeService.Tick`. 보간 없음.
- `MainScene`(씬 스크립트): `Awake`에서 `GameManager.Instance.Init()` → `UIManager.Open<…View>` → Presenter 생성자 주입 → `WorldManager.Instance.Initialize(state, income, tables)`. `OnDestroy`에서 Presenter `Dispose`.
- UI만 MVP(View MonoBehaviour + 순수 C# Presenter, 생성 직후 1회 초기 갱신). 월드는 `WorldManager : MonoSingleton`(코드-규칙 v1.8, 싱글턴 예외 3번째).
- 규칙 예외(코드 주석): 레코드 `get/set`(Newtonsoft), `GameTables` 생성자 7개·`TopBarPresenter` 5개, `[SerializeField]` 빈 값 검사 안 함, 예외 메시지는 한국어.

## 2. 데이터·문구

- JSON 테이블: `animals`(v2)·`grades`·`zoo_levels`(v2)·`game_config`(v7)·`strings`·`visitors`(v1)·`facilities`(v1). 스키마는 데이터-테이블-규칙 8장.
- UI 문구는 전부 `strings.json`(`{0}` 서식, 키는 밑줄 표기). 코드·프리팹에 한국어 리터럴 금지. 큰 수는 `BigNumberFormatter`(999 · 1.2K · 3.4M · 5.6B · 7.8T).
- 동물·관광객 연출값(시트·`frameRate`·`scale`·`moveSpeed`·대기 시간)은 전부 테이블. 프리팹에 숫자 없음. 프리팹 인스펙터에 남는 건 순수 연출 숫자뿐(관광객 `m_entryMargin` 1.5·`m_viewInset` 1, `CoinPopup` 0.8/0.7, 스폰 간격 1.5초, 결과 카드 1초).
- 스프라이트 임포트 규칙(데이터-테이블-규칙 5장): 동물·관광객 PPU 300, 피벗 하단 중앙(발끝 행 자동 계산), 시트는 투명 열로 나뉜 섬 단위 슬라이스. 웜뱃 Move는 앞 4프레임만 사용. 시설 PPU 128. 타일 64×32 PPU 64.

## 3. 상태와 규칙 (Core)

- `ZooState`: `Coins`·`TotalCoinsEarned`·`PullCount`, `OwnedAnimals`(종별 `Count` = 마리 수), 시설별 단계. `AddCoins`/`TrySpendCoins`가 코인의 단일 출처. 이벤트 `CoinsChanged`·`AnimalsChanged`·`FacilitiesChanged`.
- `ZooLevelService`: 누적 획득 코인 → 레벨·`NextThreshold`(마지막이면 null), `ZooLevelReached`. 레벨의 역할은 **시설 해금**(`facilities.unlockLevel`).
- `IncomeService`: `IncomePerSecond`를 소유하고 `AnimalsChanged`·`FacilitiesChanged`에 재계산, `IncomeChanged` 발생. 수입을 읽는 곳은 전부 이것만. `Tick(dt)` = `AddCoins(수입 × dt)` 후 `ZooLevelService.Refresh()`.
- `IncomeCalculator`: 종 수입 = 기본 수입 × (1 + `incomeBonusPerAnimal` × (마리 − 1)) 합 × **Π(1 + `multiplierPerStage` × 단계)**(시설). 팝업 행 표시도 같은 수식.
- `FacilityService`: 비용 = `baseCost × costGrowth^단계`, 해금 = 레벨 ≥ `unlockLevel`, `TryUpgrade`. 홍보는 시설 테이블의 첫 행(f01)일 뿐이다.
- `GachaService`(08에서 삭제 예정): 난수 1회 추첨, 비용 `Round(100 × 1.12^n)`, `SecondsUntilAffordable` = (비용 − 코인) ÷ 수입. 등급 확률은 동물이 있는 등급만 정규화.
- `VisitorCalculator.Count(수입)`: 0 → 0, 그 외 min(12, 1 + ⌊log₂(1 + 수입)⌋). 관광객은 보여주기용, 수입은 관광객과 무관.
- 난수: 규칙은 `IRandom` 주입(`SystemRandom`, 테스트는 `SequenceRandom`), 연출은 `UnityEngine.Random` 허용(World).

## 4. UI

- 상단 바(`TopBarView`): 코인 · `초당 n` · `Lv.n` · `누적/기준`(마지막 레벨 `MAX`). Bold(가변 폰트가 얇다), 한글 폰트 `NotoSansKR SDF`.
- 가차 버튼(`GachaButtonView`): 비용 상시, 아래 `{0}초 후`, 등급 확률 한 줄. 결과 카드(`GachaResultView`)는 차단막 + 1초 뒤 스스로 닫힘. 08에서 전부 삭제.
- 꾸미기(`FacilityButtonView` → `FacilityPopupView` + 행 프리팹 `FacilityRowView`): 행마다 이름 · `n/max` · `×배수` · 비용 버튼, 잠김 `Lv.n 해금`, 최대 `MAX`. Presenter 하나(`FacilityPopupPresenter`).
- Canvas는 `UIManager`가 런타임에 만든다(1080×1920 ScaleWithScreenSize). 씬에 Canvas 없음.

## 5. 월드 (World, `WorldManager`)

- **순수 2D 쿼터뷰**. 논리 좌표 XZ(유닛 = 타일)는 `Unit.Logical`·`ZoneView`·`BranchView`의 Rect에만 있고, 화면 XY는 `Iso.ToScreen`(+X 오른쪽 위, +Z 왼쪽 위, k 0.5/0.25)으로만 만든다. 카메라 직교 size 6, 회전 없음, z −10, 배경색 잔디 (110,173,86).
- 깊이 정렬은 **화면 y**(`Renderer2D.asset` Custom Axis (0,1,0)), 정렬점 Pivot(발끝·기둥 밑). 고정 order는 잔디 배경 −2100·잔디 −2000·길 −1500·흙 −1000·경계선 −950·그림자 −900뿐. 수동 정렬 코드 없음.
- 바닥은 Unity Tilemap(Isometric Grid cellSize 1×0.5, 셀 (x,z) = 논리 (x,z)): `Ground`(잔디)·`Floor`(굴 바닥 `Yard`, 2026-09-18 흙 대체)·`Path`(길) 3층, 타일 18변형(`Assets/Tiles/{Grass,Yard,Path}_00~17`, 시트 → Tile은 `TileSheetImporter`). 서 있는 것(울타리·시설·동물·관광객·나무)은 스프라이트. 지형 경계선은 프리팹에 구운 `edge.png` 조각(존 둘레·맵 둘레), 같은 지형끼리는 선 없음.
- **존** `Zone.prefab`(`ZoneView`: `m_center`·`m_walkArea`·`m_pathArea`, 6×8 타일, 굴 입구 1장(`burrow_1`, 2026-09-18 울타리 대체) + 경계선 28개 구움. `ZoneBaker` 메뉴로 재생성). **지점** `Branch01.prefab`(`BranchView`: `m_mapArea` (−12,−12,50,56)·`m_zones[]` z01~z09 앞줄 왼쪽부터): Backdrop(무한 잔디, 주기 텍스처 Tiled) → Grid 3층 → MapEdge → 존 9개(3열 × 3줄, 원점 (2+8c, 2+10r), 사이·둘레 길 2칸, 입구 틈 앞 가운데) → Border(숲 12칸, 나무·덤불 1,330개). 맵 26×32.
- 씬에는 월드 인스턴스가 없다. `WorldManager.m_branchPrefab`을 `Branch` 프로퍼티가 처음 쓸 때 `Instantiate`. 실행 전 `World` 아래는 비어 있어야 한다. `Zone => Branch.Zones[0]`(08까지 z01만).
- 카메라 팬(`WorldCameraController`): 드래그로 초점 이동(`Pointer.current` 폴링, UI 위 시작이면 무시), 한계는 맵 화면 경계의 **내접 마름모**(초점 허용 반폭 = A − hw − (A/B)·hh, 밖이면 중심 쪽 비례 축소). 시작 초점 (−0.5, 1.25). 핀치 줌 없음.
- 개체: `Unit`(abstract) → `Animal`(`WaitState` ⇄ `WalkState`, 존 안 임의 지점) · `Visitor`(입장 → 구경(코인 팝업) → 퇴장 → `Exited`). 계층 루트(위치만) → `ModelRoot`(`scale`) → `Sprite` + `Shadow`. 프레임은 `WorldManager.Frames`(`FrameCache`, 경로당 1회, 번호 정렬). 풀링 없음.
- 관광객: `VisitorSpawner`가 `TargetCount`까지 1.5초 간격 스폰, 종류는 `visitors.weight`. 존 `PathBounds`(존 앞 길 2칸) 안을 X로 가로지르고 동물이 있으면 멈춘다. 수는 `IncomeChanged`마다 갱신.
- 시설: `Facility.prefab`을 존 자식으로 `존 중심 + (slotX, 0, slotZ)`(±2.2/±2.8, 존 안 네 모서리)에 1단계에 한 번 생성. 단계가 올라도 모습은 그대로.
- 아트 규칙: 서 있는 리소스는 웜뱃식 진갈색(52,32,32) 외곽선, 바닥은 외곽선 없음. 생성은 Codex CLI(웜뱃 참조, 흰 배경 → 키잉·팔레트 정규화·최근접 축소), 원본·스크립트는 각 폴더 `Source~/`. 지점·존은 에디터 스크립트로 한 번에 굽고 스크립트는 프로젝트에 남기지 않는다(scratchpad).

## 5-1. 화면 전환 (설계 08 1단계, 2026-09-18)

- `Navigation`(Core): `Current`(Overworld | Shop), `EnterShop()`/`ExitShop()`, `Changed`. `GameManager.Init`이 만들고 `MainScene`이 UI·World에 넘긴다. UI와 World는 서로 모르고 이 이벤트만 본다.

- `ShopHudView`/`ShopHudPresenter`(UI): 상단 바 아래 한 줄, 뒤로 버튼("지상으로") + 제목("빵집"). 가게 화면에서만 보인다. 프리팹은 `ShopBaker`(`ZooTycoon/Bake/Shop`).
