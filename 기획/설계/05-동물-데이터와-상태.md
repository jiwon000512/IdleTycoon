# 설계 05 — 동물 데이터와 상태 (웜뱃)

상태: 구현 완료 · 2026-09-14
기능: 동물의 스탯·연출값을 전부 `animals.json`으로 옮기고, 동물 개체를 명시적 상태(Idle·Move) + 프레임 애니메이션으로 만든다. 더미 8종을 버리고 실제 아트가 있는 웜뱃 1종으로 시작한다.
기획서 대응: 6.1 동물 표(v0.11), 6.2 수입, 8장 아트 파이프라인
다음 기능: 06 관광객

---

## 0. 결정

### 0.1 사용자 확정 (2026-09-14)

| # | 결정 | 이유 |
|---|---|---|
| D1 | **더미 8종 삭제, 웜뱃 1종만.** 실제 아트가 오는 종부터 한 종씩 추가 | 더미로는 동물을 구체화할 수 없다 |
| D2 | 상태는 **Idle·Move 두 개** | 리소스가 idle·move 시트뿐. 상태 추가는 enum + case + 시트 칼럼 |
| D3 | 동물 스탯·연출값은 **전부 데이터**(`animals.json`). 프리팹에 숫자 0개 | 종마다 다른 값을 코드·프리팹에 두지 않는다 |

### 0.2 설계 제안

| # | 제안 | 이유 |
|---|---|---|
| P1 | `animals.json` **version 2**: `idleSheet`·`moveSheet`(null 허용), `frameRate`, `scale`, `moveSpeed`, `idleSecondsMin`·`idleSecondsMax` 추가 | D3. 시트가 null이면 `sprite` 1장을 프레임 1개로 쓴다(`Resources.LoadAll`이 Single 텍스처에서도 1장을 돌려준다) |
| P2 | 등급 확률은 **동물이 있는 등급만 정규화**. 빈 등급은 0, 버튼 확률 줄에서 숨김. 검증 규칙 "등급별 최소 1종" 삭제 | 종이 1개면 희귀·전설이 비는데 27%·3%를 표시하면 거짓이다. 등급 테이블은 그대로 두고 종이 늘면 저절로 돌아온다 |
| P3 | `AnimalActor`: `AnimalState { Idle, Move }` + `switch`. 상태 진입 메서드 `EnterIdle`/`EnterMove`가 타이머·목적지·애니메이션을 바꾼다. State 패턴 클래스 없음 | 두 상태에 클래스 계층은 과하다. 상태 추가는 enum 값 + Enter 메서드 + case |
| P4 | `SpriteAnimator`(World, MonoBehaviour): `Play(Sprite[] frames, float frameRate)`, `Update`에서 프레임 순환. Unity Animator·AnimationClip 안 씀 | 동물마다 컨트롤러 에셋을 만들면 JSON 주도가 깨진다. 관광객(06)도 같은 컴포넌트 |
| P5 | 프레임 로드는 `WorldView.SpawnAnimal(AnimalRecord, cage)`에서 `Resources.LoadAll<Sprite>(sheet)` 이름순 정렬. 캐시 없음 | 스폰은 뽑기 때만 일어난다. Unity가 텍스처·스프라이트를 이미 캐시한다 |
| P6 | 크기는 `scale`(루트 `localScale`, 그림자 포함). 임포트 규칙: **실제 아트 PPU 300, 피벗 하단 중앙, 시트는 가로 1행 격자 슬라이스** | PPU를 종마다 바꾸면 데이터가 meta에 숨는다. 규칙은 데이터-테이블-규칙 5장에 적는다 |
| P7 | 웜뱃 임포트는 CLI 에디터 스크립트로: `wombat.png` Single·피벗 하단, 시트 2개 6×1 격자(362×724) | 자동 슬라이스가 인접 프레임을 합쳐 놓았다(3덩이). 스크립트는 프로젝트에 남기지 않는다 |
| P8 | `WorldPresenter`는 `AnimalRecord`를 넘긴다(스프라이트 로드는 World) | 스탯·시트가 전부 레코드에 있으니 스프라이트만 따로 넘길 이유가 없다 |
| P9 | 기획서 6.1 표를 웜뱃 1행으로 바꾸고 v0.11. 6.3 리듬 표(8종 기대 수입 2.95/회)는 **그대로 두고 주석**만 | 종이 늘 때 다시 계산한다. 지금 튜닝은 의미가 없다 |

## 1. 코드 설계

### 1.1 계층

asmdef·참조 변경 없음. World는 이미 Core를 본다.

### 1.2 클래스

| # | 계층 | 클래스 | 책임 · 공개 API | 상태 |
|---|---|---|---|---|
| 1 | Core | `AnimalRecord` | + `IdleSheet`, `MoveSheet`(string, null 허용), `FrameRate`, `Scale`, `MoveSpeed`, `IdleSecondsMin`, `IdleSecondsMax`(double) | 수정 |
| 2 | Core | `GachaTable` | 등급 가중치 합을 동물이 있는 등급만으로. `GradeProbability`는 빈 등급 0(P2) | 수정 |
| 3 | Data | `TableValidator` | "등급별 최소 1종" 삭제. 추가: `frameRate > 0`, `scale > 0`, `moveSpeed > 0`, `0 ≤ idleSecondsMin ≤ idleSecondsMax` | 수정 |
| 4 | World | `AnimalState`(enum) | `Idle`, `Move` | 신규 |
| 5 | World | `SpriteAnimator` | `[SerializeField] SpriteRenderer`. `Play(Sprite[] frames, float frameRate)`(P4) | 신규 |
| 6 | World | `AnimalActor` | `Initialize(AnimalRecord, Sprite[] idle, Sprite[] move, CageView, Quaternion billboard)`. FSM(P3). 직렬화 필드: 렌더러 2개 + `SpriteAnimator`. 숫자 필드 없음 | 재작성 |
| 7 | World | `WorldView` | `SpawnAnimal(AnimalRecord, int cageIndex)`. 프레임 로드(P5) | 수정 |
| 8 | World | `WorldPresenter` | 레코드를 넘김(P8) | 수정 |
| 9 | UI | `GachaButtonPresenter` | 확률 줄에서 확률 0 등급 제외(P2) | 수정 |
| 10 | Tests | `AnimalSpriteFileTests` | `sprite`·`idleSheet`·`moveSheet`(null 아닌 것) 파일 존재 | 수정 |

### 1.3 상태 흐름

```
Initialize → EnterIdle
Idle : timer -= dt; 0 이하 → EnterMove   (목적지 = cage.RandomWalkPoint, flipX = 왼쪽, Play(move))
Move : MoveTowards(moveSpeed); 도착 → EnterIdle (timer = Random(idleMin, idleMax), Play(idle))
```

## 3. 구현 결과 (2026-09-14)

| # | 달라진 점 | 이유 |
|---|---|---|
| C1 | 시트 슬라이스는 `importer.GetSourceTextureWidthAndHeight`(원본 2172×724) 기준. 첫 시도는 Max Size 2048로 줄어든 텍스처 크기를 써서 341×683으로 잘못 잘렸다 | 스프라이트 rect는 원본 픽셀 좌표다. 시트 Max Size는 4096으로 |
| C2 | `wombat.png`(정지 그림)는 1254px라 PPU 300에서 4.18유닛. 카드 UI에서만 쓰므로 그대로 둠 | 월드에는 시트만 쓴다 |
| C3 | 웜뱃 시트는 프레임이 맞닿아 있어 경계에서 이웃 프레임 조각이 몇 픽셀 비친다 | 아트 문제. 사용자가 다시 뽑기로 함. 코드·데이터 변경 없음 |
| C5 | 사용자가 프레임 간격을 띄운 시트로 교체(파일명 `Wombat_Idle`·`Wombat_Move`, JSON 경로도 맞춤). 간격이 균등하지 않아 격자 슬라이스가 어긋나서, **투명 열로 나뉜 섬을 프레임으로 잡고 시트별 최대 섬 폭으로 통일·섬 중심 정렬**하는 방식으로 바꿈. **시트별 PPU를 몸 높이 기준으로 정규화**(Idle 300, Move 295), 피벗 y는 시트별 발끝. Move는 사용자 요청으로 앞 4프레임만 사용(1→2→3→4 반복) | 격자 가정은 아트 도구가 보장하지 않는다. 섬 기준이면 어떤 간격이든 맞는다 |
| C4 | **버그 수정(사용자 스크린샷)**: 발이 그림자 위로 떠 보였다. 원인은 시트 프레임 아래 219px 여백 + 피벗 하단이라 발끝이 땅에서 0.73유닛 위에 있던 것. 피벗 y를 발끝 행 ÷ 높이(0.302, 두 시트 공통)로 자동 계산해 임포트. 프리팹 계층도 `AnimalActor → ModelRoot(scale) → Sprite(빌보드) + Shadow`로 재구성해 루트는 위치만 갖는다 | 사용자 지시 구조. 루트가 회전·크기를 갖지 않아 위치·정렬 계산이 단순해진다 |

검증: 컴파일 0 · 콘솔 0 · EditMode 76/76 · 플레이: 뽑기 3회 → 웜뱃 3마리, 1초 간격 조회에서 프레임 이름이 바뀜(idle_0→3, move_1→5), Idle↔Move 전환, 왼쪽 이동 시 `flipX`, `scale` 1, 확률 줄 `일반 100%`, 버튼 `60초 후`. C4 이후: 루트 회전 0·Sprite 55°, 발끝(피벗)이 그림자 y 0.02와 일치, 캡처에서 몸이 그림자를 덮음.
