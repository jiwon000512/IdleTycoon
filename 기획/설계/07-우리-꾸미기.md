# 설계 07 — 우리 꾸미기 (시설)

상태: 구현 완료 · 2026-09-15
기능: 우리는 지점당 하나다. 성장은 우리 주변 정해진 자리에 시설·장식을 사서 단계를 올리는 것이고, 시설마다 전체 수입 배수가 붙는다. 홍보는 시설 테이블의 첫 행이고, 동물원 레벨은 시설을 해금한다. 이전 로드맵의 07(우리 해금·맵 확장)과 08(홍보 팝업)을 이 기능 하나가 대체한다.
기획서 대응: 2장 배치·시설·목표 장치, 3장 루프 3~5, 4장 월드 시설·HUD 꾸미기 탭, 6.4 시설·동물원 레벨, 8장 데이터 (v0.16)
다음 기능: 08 저장·로드·오프라인 수익 팝업

---

## 0. 결정

### 0.1 사용자 확정 (2026-09-15)

| # | 결정 | 이유 |
|---|---|---|
| D1 | **우리는 지점당 하나.** 우리 해금·격자 배치·맵 확장·개방 전 우리 표시를 전부 폐기. 씬의 테스트용 우리 2개(뒤·앞) 삭제 | 사용자 지시. 우리를 늘리는 대신 그 우리를 꾸민다 |
| D2 | 꾸미기의 본체는 **시설·장식 아이템 배치** (고양이와 스프 방식). 우리 단계 업그레이드(9.1 C5)는 안 한다 | 아이템 하나가 곧 판매 행 하나라 테이블로 늘리기 쉽다 |
| D3 | 아이템은 **정해진 자리(슬롯)에 자동**으로 놓인다. 좌표는 JSON, 이동·드래그 없음 | 배치 UI·격자·겹침 판정·저장 좌표가 필요 없다 |
| D4 | 수입 효과는 **아이템마다 단계 + 전체 수입 배수**. 홍보(10단계, 단계당 +10%)가 첫 행 | 수식이 하나로 통일된다. 관광객 × 단가(C3)는 이후 유형 칼럼으로 |
| D5 | 해금은 **동물원 레벨**(`facilities.unlockLevel`). `zoo_levels`의 `cageCount`·`unlocksPromotion`은 삭제 | 레벨 구조 유지, 레벨업 = 새 시설 판매 시작 |
| D6 | 첫 버전 범위는 **홍보 + 더미 아이템 3개**(벤치·매점·나무), 팝업 하나 | 실제 아트가 오면 행만 늘린다 |

### 0.2 설계 제안

### 1.3 흐름

```
꾸미기 버튼 → 팝업 열기 → 행마다 Refresh(name, stage/max, ×배수, 비용 | Lv.n 해금 | MAX, interactable = CanUpgrade)
행 클릭 → FacilityService.TryUpgrade(id) → ZooState.TrySpendCoins + UpgradeFacility → FacilitiesChanged
   ├→ IncomeService 재계산 → IncomeChanged → 상단 바 수입·관광객 수
   ├→ WorldPresenter.SyncFacilities → 1단계가 된 시설을 우리 옆에 스폰
   └→ FacilityPopupPresenter 행 갱신
ZooLevelReached → 행 갱신(잠김 → 비용)
```

## 3. 구현 결과 (2026-09-15)

| # | 달라진 점 | 이유 |
|---|---|---|
| C1 | **시설 자리를 우리 바깥(x ±6.2·±6.5)에서 우리 안 네 모서리로 옮겼다**(P7·1.4·`facilities.json`). 첫 플레이 캡처에서 산 시설이 화면에 안 보였다: 세로 화면은 길 깊이에서 x ±5유닛만 보인다. "우리를 꾸민다"이므로 우리 안이 자연스럽다 | 캡처로 발견한 버그. 기획서 4장·6.4, 데이터-테이블-규칙 8.6 함께 수정 |
