# UI 작업 규칙

버전 v1.0 · 2026-09-27. **세션마다 읽는다.** UI(팝업·버튼·HUD·말풍선)를 만들거나 고칠 때 반드시 따른다. 단위·팔레트·폰트 숫자는 `UI-디자인-규칙.md`.

## 1. 원칙

1. **공용 조각이 먼저다(1원칙).** 새 화면·부품은 아래 2장의 공용 조각으로 먼저 만든다. 맞는 조각이 없을 때만 새로 뽑는다(Codex CLI). 비슷한 조각을 화면마다 따로 만들지 않는다.
2. **한 역할에 한 조각.** 닫기·버튼·틀·카드·탭·알약·말풍선·코인은 게임 전체에서 한 벌만 쓴다. 한 팝업 안에서 두 벌이 섞이면 버그로 본다.
3. **조각에 특정 리소스를 박지 않는다.** 코인·아이콘·글자·그림이 들어간 틀(옛 `pill_cost`처럼 코인이 박힌 알약)은 만들지 않는다. 틀은 틀만, 아이콘·글자는 따로 얹는다.
4. **이름은 역할로.** 공용 조각은 `btn_primary`·`bubble`처럼 역할 이름을 쓰고, 화면 접두사(`clerk_`·`nego_`)는 그 화면에만 있는 그림(협상 무대·나무 자 바)에만 쓴다.
5. **새로 뽑는 리소스는 하나씩.** Codex로 한 조각씩 뽑아 사용자에게 보여 주고, 확인받은 뒤 인게임에 적용한다. 여러 개를 한 번에 뽑아 적용하지 않는다.
6. **한 글에 정보 하나.** 「·」「/」로 정보 두 개 이상을 한 텍스트에 잇지 않는다. 폰트 굵히기·그림자는 쓰지 않는다(2026-09-26 반려).
7. **UI 프리팹이 원본이다.** 값 수정은 프리팹을 직접 고친다(`PrefabUtility.LoadPrefabContents` → 값 → 저장). UI 전체를 다시 굽지 않는다(코드 규칙 v1.18).
8. **픽셀은 정수 배.** 스프라이트는 원본의 정수 배 크기로 놓는다(9-slice는 가운데만 늘어나므로 예외). 비정수 배는 뭉개진다.

## 2. 공용 조각 (2026-09-27)

`Assets/Sprites/UI/`(월드는 `Sprites/World/`). 교체 진행 중인 것은 「예정」.

| 역할 | 조각 | 비고 |
|---|---|---|
| 닫기 | `btn_close` | 다른 닫기 그림은 두지 않는다 |
| 카드·줄 | `row` | 목록 한 줄(점원 카드·사물 시트 줄) |
| 말풍선 | `bubble` + `bubble_tail` | 9-slice 몸통 + 꼬리(웜뱃 쪽으로 옮기고, 오른쪽은 좌우 뒤집기) |
| 코인 | `World/coin` | UI·월드 공용 |
| 주 버튼 | 예정(Codex) | 지금 `btn_primary`·`clerk_btn` 두 벌 → 하나로 |
| 팝업 틀 | 예정(Codex) | 지금 `sheet_frame`·`clerk_panel` 두 벌 → 하나로 |
| 탭·선택 칩 | 예정(Codex) | `clerk_tab`·`chip_hi`·`chip` 대체 |
| 알약 | 예정(Codex) | `clerk_slot`·`pill_cost`·`pill_hud` 대체. 코인·아이콘은 따로 얹는다 |
| 보조 버튼 | `btn_secondary` | |
| 행동 버튼(원형) | `btn_act` | |

화면 전용(공용 아님): 협상 `nego_scene`·`nego_bar`·`nego_bar_tick`·`nego_arrow`·`nego_ribbon`, 점원 `clerk_frame`·`clerk_frame_empty`·`clerk_badge_*`·`clerk_table`·`clerk_gauge*`.

## 3. 새 조각 뽑기 절차

1. 2장에서 쓸 수 있는 조각이 있는지 먼저 본다. 있으면 그것을 쓴다.
2. 없으면 Codex CLI로 **한 조각** 시안을 뽑는다(`아트-프롬프트.md` 0장 스타일, 지금 게임 캡처·공용 조각을 참조로). 코인·아이콘·글자는 넣지 않는다.
3. 게임 크기로 비교 페이지(아티팩트)를 만들어 사용자 확인을 받는다.
4. 확인되면 칸 단위 PNG로 만들어(원본 스크립트는 `Sprites/UI/Source~/`) 공용 이름으로 저장하고, 옛 조각을 쓰던 곳을 모두 바꾼 뒤 옛 조각을 지운다. 캡처로 확인한다.
5. 2장 표를 갱신한다.
