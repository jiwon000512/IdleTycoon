## 도구 함정 (Unity CLI)

- 구현·에셋 작업 전 `editor_status`의 `playMode` 확인. 플레이 중이면 씬 저장·프리팹 교체가 틀어진다. `run_tests`는 반드시 `editor_stop` 후 `playMode=stopped`에서 `--mode EditMode --timeout 150`으로 **한 번만** 호출(같은 명령을 파이프로 두 번 부르면 두 번째가 겹쳐 테스트 러너가 깨지고 파이프라인이 막힌다. 2026-09-18). 막히면 `taskkill //F //PID`로 에디터를 죽이고 **`ProjectTycoon/Temp/UnityLockfile`을 지운 뒤** `unity projects open`(잠금 파일이 남으면 모달이 떠 영원히 연결되지 않는다).
- `eval`은 5초 넘으면 타임아웃 오류를 콘솔에 남긴다(스프라이트 여러 장 임포트하는 굽기). 작업은 끝나 있으니 프리팹을 조회해 확인하거나 `run_script`로 굽는다.
- 프리팹을 다시 구운 뒤에는 플레이를 새로 시작한다(이미 돌던 세션은 옛 프리팹으로 만든 개체를 그대로 쓴다).
- `capture_game_view --save_path`는 프로젝트 안 경로만 받고 `Temp/x.png`가 `Assets/Temp/`에 저장된다(에셋으로 임포트됨). 확인 뒤 `AssetDatabase.DeleteAsset("Assets/Temp")`.
- 에디터가 포커스를 잃으면 플레이 프레임이 멈춘다(`editor_focus`도 곧 풀림). 긴 관찰은 플레이 중 `Application.runInBackground=true`를 eval로 켠다(런타임만, 저장 안 됨).
- 에디터 창이 뒤에 있으면 플레이 프레임이 멈춘다 → `editor_focus`. **편집 모드에서 모든 명령이 30초 타임아웃되는데 포트는 ready·프로세스는 응답·모달 없음이면 에디터 메인 스레드가 멈춘 것**(2026-09-23 10:58, 플레이 종료 `editor_stop` 직후 `eval`로 `AssetDatabase.DeleteAsset(\"Assets/Temp\")`를 부른 다음 발생. 라이선스 클라이언트 로그의 주기 요청이 그 시각에 끊기고 CPU 0, 전경으로 올려도 반응 없음). 파이프라인은 명령을 `EditorApplication.update`에서 꺼내므로 update가 멈추면 배경 명령까지 실행 게이트(한 번에 하나) 뒤에서 같이 죽는다 — 재시도를 1분마다 보내면 게이트를 더 막으니 하지 말 것. 복구는 taskkill → `Temp/UnityLockfile` 삭제 → `unity projects open`뿐. 예방: 플레이 종료 뒤 `editor_status`로 `playMode=stopped`를 확인한 다음에 에셋 삭제/임포트를 부른다. Interaction Mode는 No Throttling(레지스트리 값 1)로 바꿔 둠(배경 절전 배제용, 이 멈춤의 원인은 아님).
- 같은 경로에 에셋을 다시 만들 때는 `DeleteAsset` → `CreateAsset` → 프리팹 `ImportAsset(ForceUpdate)` → `recompile` 뒤 플레이(옛 객체가 "이름 없는 Tile"로 남는다).
- 콘솔 로그 조회는 `console --json`(`console_logs` 명령은 없다. 잘못 부르면 그 호출 자체가 콘솔 오류 1건으로 남는다).
- 여러 줄 C#은 `run_script --file --entry --mode ephemeral`. 일회성 조립·조회 스크립트만 scratchpad, 프리팹을 통째로 만드는 스크립트는 `Scripts/Editor`에 MenuItem으로. `GetComponent ?? AddComponent`는 가짜 null로 실패 → `TryGetComponent`.
- 플레이 중 상태는 `GameManager.Instance.State/...`를 `run_script`로 읽는다. 1초짜리 연출은 캡처 대신 상태 조회. 정확한 화면 좌표는 `capture_game_view --source camera --width 1080 --height 1920`.
- 콘솔의 `TreeViewController NullReference`·`GUIClips`는 Hierarchy 창의 에디터 내부 오류. 게임 오류 판정은 `error CS`·게임 스택만.
- Git Bash는 `export MSYS_NO_PATHCONV=1`. 에디터 열기 `unity projects open ProjectTycoon`, 연결 확인 `unity pipeline list`.
- 에디터 게임 뷰가 가로 1280×720이라 `--source screen` 캡처는 가로로 나온다. UI까지 세로로 확인하려면 플레이 중 캔버스를 `ScreenSpaceCamera` + `sortingOrder` 5000으로 바꾼 뒤 `--source camera --width 540 --height 960`(scratchpad `TapCheck.cs`). 재컴파일은 플레이가 끝날 때까지 미뤄지므로, 플레이 중 컴파일 0은 새 코드를 검사한 결과가 아니다.
