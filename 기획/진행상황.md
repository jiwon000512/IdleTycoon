## 알아야 할 것

- **개발 절차(코드-규칙 v1.5)**: 설계 → 사용자 확정 → 한 번에 구현(Unity CLI) → **에이전트가 1회 실행해 검증**(컴파일 0·콘솔 0·EditMode 테스트·플레이 모드 캡처) → 짧게 보고. 테스트 방법 문서 없음, 문서화 최소.
- 기능을 완성할 때마다 `기획/포트폴리오.md` 4장에 한 절(기술 포인트·AI가 한 일·문제와 해결)과 5장 숫자를 갱신한다. 게임이 매출을 못 내면 포트폴리오로 쓴다.
- 에디터 열기: `unity projects open ProjectTycoon`(`project`가 아니라 `projects`). 연결 확인 `unity pipeline list`. Git Bash에서는 `export MSYS_NO_PATHCONV=1`.
- Unity CLI 요령:
  - **구현 시작 전 `editor_status`의 `playMode`를 확인한다.** 플레이 중이면 씬 저장·`OpenScene`이 실패한다(03에서 겪음). 사용자가 켠 플레이 모드면 끄기를 기다린다.
  - 검증 순서: `editor_play` → `console` 오류 0 → `capture_game_view --source screen` → `editor_stop` → `editor_status`로 `playMode=stopped` 확인 → `run_tests`.
  - 여러 줄 C#은 `unity cmd run_script --file <절대경로> --entry <Type.Method> --mode ephemeral`. 에디터 스크립트로 프리팹·스프라이트를 만들 때 이 방식이 가장 확실했다(02에서 프리팹 3개·PNG 8개 생성). 스크립트는 scratchpad에 두고 프로젝트에 남기지 않는다.
  - `console`의 인자는 `--tail N --level warn`.
  - **에디터 창이 뒤에 있으면 플레이 모드 프레임이 멈춘다**(`Time.frameCount` 고정, 코루틴·이동 안 돎). `editor_focus`로 앞에 가져오면 돈다. `set_autotick --enable true`는 소용없었다.
  - 플레이 중 버튼은 `run_script`로 `Button.onClick.Invoke()` 호출로 누를 수 있다. 명령 1회 지연이 1초 넘어 1초짜리 결과 카드는 캡처보다 상태 조회(`FindFirstObjectByType`)로 확인한다.
  - `run_tests`를 플레이 모드에서 돌리면 파이프라인이 영구히 막힌다(사람이 Unity 창에서 Stop 해야 풀림). 반드시 `editor_stop` 후 `playMode=stopped`를 확인하고 돌린다.
- 플레이 중 상태를 보려면 `run_script`에서 `ZooTycoon.Game.GameManager.Instance.State/Gacha/ZooLevel`을 바로 읽는다(리플렉션 불필요). 레벨 판정은 틱에서만 하므로 `AddCoins` 직후가 아니라 다음 틱(1초) 뒤에 `Lv`가 오른다.
- 리소스는 JSON 경로 칼럼(`animals.sprite`)으로 참조. 더미가 들어 있고 사용자가 같은 경로로 실제 리소스를 덮어쓴다.
- **UI 문구는 전부 `strings.json`**. 코드·프리팹에 한국어 리터럴 금지(예외 메시지 제외). 새 화면은 문구 키부터 추가.
- 의존 방향 `Game → UI → Core`, `Game → World → Core`, `Game → Data → Core`. UI와 World는 서로 모른다. 레코드·`GameTables`·`StringTable`은 Core, `TableValidator`만 Data.
- 스프라이트·등급 색 읽기는 UI `AnimalVisuals`(static). World는 `Resources.Load<Sprite>`를 직접 한 줄 호출. 등급 색은 `grades.colorHex`.
- **월드는 XZ 평면(y = 0)**, 화면 위 = +Z. 카메라는 원근(FOV 60) 55° 내려다봄, 초점(XZ)에서 거리 17. 우리 9.6 × 12.2유닛. 동물 스프라이트는 PPU 128·피벗 하단 중앙(실제 리소스로 교체할 때도 같은 설정), 런타임에 카메라 기울기로 세운 카드.
- 깊이 정렬은 카메라 거리(URP 2D Renderer Transparency Sort Mode = Default). 땅 −1000·그림자 −900·잔디 −2000만 고정 order. 수동 y 정렬·축소 코드 없음.
- 동물 연출값은 **전부 `animals.json`**(시트·frameRate·scale·moveSpeed·idleSeconds). 프리팹 `AnimalActor`에는 숫자가 없다. 그 외 월드 연출값은 인스펙터: 우리 이동 영역(`CageView.m_walkArea`, XZ), 카메라 기울기·거리·시작 초점(Main Camera `WorldCameraController`), 팬 여유(`World`의 `m_panMargin`).
- 웜뱃 시트는 사용자가 프레임 간격을 띄운 픽셀아트로 교체(`Wombat.png`, `Wombat_Idle.png`, `Wombat_Move.png`). 프레임 간격이 균등하지 않아 격자 대신 **투명 열로 나뉜 섬 단위 슬라이스**(폭 통일·중심 정렬)로 임포트. 새 시트가 오면 같은 스크립트 방식(데이터-테이블-규칙 5장)으로 다시 자른다. `Wombat_Move`는 6프레임 픽셀 시트의 **앞 4프레임만 스프라이트로 만들어 1→2→3→4→1 반복**(사용자 요청, 5·6번 섬은 건너뜀). 몸 높이 260px vs Idle 264px라 PPU 295로 정규화. PNG는 그대로이므로 다시 자를 때 이 예외를 유지할 것.
- **동물 프리팹 계층**: `AnimalActor`(루트, 땅 위 XZ 위치, 회전·크기 없음) → `ModelRoot`(`localScale` = `animals.scale`) → `Sprite`(SpriteRenderer, 빌보드 55°) + `Shadow`(눕힘, y 0.02). 시트 피벗 y는 발끝 행 자동 계산(데이터-테이블-규칙 5장). 발이 그림자 위로 뜨면 피벗을 의심할 것.
- 플레이 모드 없이 카메라 프레이밍을 보려면: eval로 카메라 위치를 `초점 − forward × 거리`로 놓고 `capture_game_view --source camera --width 540 --height 960`.
- 종 → 우리 배정은 **임시**로 보유 순서 % 우리 수(`WorldPresenter`). 06에서 규칙 확정.

## 알려진 문제

- **빌드 타깃이 Standalone이다.** 기술 결정은 Android IL2CPP ARM64인데 아직 안 바꿨다. 제품명·회사명·패키지 ID도 임시(DefaultCompany).
- 폰트가 가변 폰트라 기본 굵기가 얇다. 텍스트는 전부 Bold.
- 씬의 `Global Light 2D`는 원근 카메라에서도 스프라이트를 비추지만, 2D 라이트가 필요 없어지면 URP 2D Renderer → Universal Renderer 전환을 검토한다.
- 씬의 우리 3개 중 뒤·앞 우리는 **테스트용**이다. 06에서 우리 해금·배치 규칙을 정하면 씬 구성을 다시 잡는다. `zoo_levels.cageCount`(3~9)도 06에서 재정의.
