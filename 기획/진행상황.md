## 알아야 할 것

- 개발 절차: 설계(코드+QA) → 사용자 검증 → 한 번에 구현(Unity CLI) → QA → 보고. 기능 하나 = 세션 하나.
- 에디터가 열려 있으면 `unity pipeline list`로 연결 확인 후 라이브 CLI 사용. Git Bash에서는 `export MSYS_NO_PATHCONV=1`.
- Unity CLI 요령(이번 세션에서 확인):
  - 여러 줄 C#은 `unity cmd run_script --file <절대경로> --entry <Type.Method> --mode ephemeral`. `--mode editor`는 없는 값이다.
  - `capture_game_view --save_path`는 **프로젝트 루트 안**만 허용한다(`Temp/x.png` → `Assets/Temp/x.png`). 쓰고 나서 지울 것.
  - `console`의 인자는 `--tail N --level warn`.
  - **`run_tests`는 플레이 모드에서 절대 돌리지 말 것.** EditMode 러너가 씬을 저장하려다 `InvalidOperationException: This cannot be used during play mode`로 죽고, 그대로 **파이프라인 실행 큐가 영구히 막힌다**(이후 모든 `unity cmd`가 타임아웃). 백그라운드 프로세스는 Windows 포그라운드 잠금 때문에 에디터 창을 다시 활성화할 수 없으므로, 사람이 Unity 창을 눌러 Stop(Ctrl+P)을 눌러야 풀린다. `run_tests` 앞에 `editor_stop` → `editor_status`로 `isPlaying=false`를 **확인**하고 돌릴 것.
- 리소스는 JSON 경로 칼럼(`animals.sprite`)으로 참조. 더미 리소스가 들어 있고 사용자가 같은 경로로 실제 리소스를 덮어쓴다.
- **UI 문구는 전부 `strings.json`에서 온다.** 코드·프리팹에 한국어 리터럴 금지(예외 메시지는 제외). 새 화면을 만들면 문구 키를 먼저 추가한다.
- 의존 방향이 `Game → UI`다(코드-규칙 v1.2). UI는 Game을 참조하지 않는다. 레코드·`GameTables`·`StringTable`은 Core, `TableValidator`만 Data.

## 알려진 문제

- **빌드 타깃이 Standalone이다.** 기술 결정은 Android IL2CPP ARM64인데 아직 안 바꿨다. 제품명·회사명·패키지 ID도 임시(DefaultCompany).
- `capture_game_view --source screen`은 에디터 게임 뷰 창의 백버퍼(1280×720)를 찍는다. 게임 뷰 해상도를 1080×1920으로 지정해 두었지만 캡처 크기에는 반영되지 않는다. 세로 화면 비율 확인이 필요하면 실기기나 빌드로 봐야 한다.
- 폰트가 가변 폰트라 기본 굵기가 얇다. `TopBarView.prefab`의 텍스트는 Bold로 두어 가독성을 확보했다.
