> **원본은 아티팩트로 옮김** https://claude.ai/artifact/Gu4ULj8nQboKNC9gVdLfiA — 이 파일은 v0.3 사본(v0.4부터는 아티팩트에만)이며 더 갱신하지 않는다.

초안 v0.3 · 2026-09-18 · 사용자 확정 전. 확정되면 기획서 v0.23에 옮긴다. 기획 출처: 「사업가 웜뱃」 기획서 아티팩트(https://claude.ai/artifact/TQaPKFEcLafuVm4WNitbGv).

**v0.2 → v0.3 (사용자 지적, 2026-09-18)**: v0.2는 줄 게이지·러시 종·쿵·카운터 버튼 같은 **HUD로 돌아가는 게임**이었다. 사용자가 원한 것은 **손님 동물이 실제로 들어와 진열대에서 빵을 집고 계산대에서 사서 나가는 흐름**이다. 사용자 답 4개:

| 질문 | 답 |
|---|---|
| 손님 흐름 | 문 → **진열대**(빵 집기, 재고 감소) → **계산대 줄** → 웜뱃 계산 → 코인 → 문 밖 |
| 플레이어 역할 | 손님·웜뱃은 자동. 플레이어는 **업그레이드** + **오븐에서 만들 빵을 골라 굽기**(일정 시간 뒤 진열대 재고에 채워짐) |
| 손님이 집는 빵 | 손님마다 **원하는 빵**이 있다(말풍선). 재고가 없으면 진열대 앞에서 참다가 **화내며 그냥 나간다** |
| 업그레이드 | **오븐 · 진열대 · 계산대 · 새 빵 해금** 전부 |

러시·쿵·줄 게이지·카운터 탭 버튼은 뺀다(v0.2의 5장 결정 1·2·5도 함께 사라진다).

**구현 상태**: 1단계 "화면 전환"은 구현·검증 완료(미커밋) — `Navigation`, 존 탭 → 카메라 (1000, 0) 점프·팬 잠금, `ShopHudView`(지상으로·제목), `ShopBaker`, 더미 배경. v0.3에서도 그대로 쓴다. 더미 배경은 아래 1.1 배치로 다시 그린다.

**이 기능의 목적**: "빵을 골라 굽는다 → 손님이 줄줄이 사 간다 → 모자란 빵이 보인다 → 업그레이드한다"를 사용자가 3분 플레이하고 끌리는지 판정한다.

### 1.1 가게 내부 배치

세로 한 화면(폭 6.75 × 높이 12유닛, 루트 (1000, 0)). 위에서 아래로:

| 요소 | 위치(유닛, 루트 기준) |
|---|---|
| 출입문(진입·퇴장) | (0, +4.6) |
| 진열대 3칸(빵 종류당 한 칸) | y +2.4, x −2.0 · 0 · +2.0. 손님 서는 자리 = 칸 + (0, +0.8) |
| 계산대 + 웜뱃 | 계산대 (−1.6, −0.6), 웜뱃 (−1.6, −1.3) |
| 계산대 줄 8칸 | 1행 y +0.3: x −1.6, −0.6, +0.4, +1.4 · 2행 y +1.2: x +1.4, +0.4, −0.6, −1.6 (앞에서부터) |
| 오븐 1~3 | y −3.2, x −2.0 · 0 · +2.0 (잠긴 오븐은 어둡게) |
| HUD | 아래 띠: 업그레이드 버튼. 위: 지상으로(기존) |

진열대 칸 위에 재고 숫자, 오븐 위에 진행 막대(월드 스프라이트)를 그린다.

## 2. 규칙

- **도착**: `arrivalSeconds`(4초)마다 1명. 가게 안 손님이 `maxCustomers`(8)이면 도착하지 않는다 — 줄 8칸이 넘치지 않는 이유.
- **원하는 빵**: 해금된 빵 가운데 `breads.weight` 가중치로 하나.
- **진열대**: 문에서 걸어와(`walkSeconds` 뒤) 원하는 빵 칸 앞에 선다. 재고가 있으면 1개 집고 계산대 줄 끝으로. 없으면 `patienceSeconds`(6초)까지 기다리고, 그 사이 재고가 생기면 집는다. 넘기면 화난 말풍선 → 퇴장(수입 없음).
- **계산**: 줄 머리를 웜뱃이 `checkoutSeconds`(1.5초 ÷ 계산 속도 배수)에 처리 → `price` 코인 지급 → 퇴장.
- **굽기**: 빈 오븐을 탭하면 해금된 빵 목록이 뜬다. 고르면 `bakeSeconds ÷ 굽기 속도 배수` 뒤 `batchSize`개가 그 빵 칸에 들어간다. 칸 용량(`shelfCapacity`)을 넘는 만큼은 버린다. 다 구우면 오븐은 다시 빈다(자동 반복 없음 — 플레이어가 들어와 누르는 이유).
- **시간**: 규칙 틱은 기존 1초(`income.tickSeconds`). 걷기는 Core가 시간으로만 알고(`walkSeconds`), World는 그 시간 안에 도착하도록 구간 거리 ÷ 시간으로 속도를 정한다. 그래서 화면과 규칙이 어긋나지 않고, 11(오프라인)에서 같은 시뮬을 화면 없이 돌릴 수 있다.
- 시뮬은 화면과 무관하게 돈다(지상에 있어도 빵이 팔린다).

## 3. 코드 구조

```
Core/Shop/
  ShopSim        규칙 단일 소유자. Tick(dt), TryBake(ovenIndex, breadId), TryUpgrade(upgradeId), TryUnlock(breadId)
  Customer       Id · BreadId · Phase(Entering|AtShelf|Queued|Checkout|Leaving) · Timer · Angry
  Oven           BreadId(null=빔) · Remaining
  ShopState      재고(breadId→개수) · 해금 빵 · 업그레이드 단계 · 오븐들 · 손님들. 저장 모델은 11
Core/Navigation  (완료)

ShopSim 이벤트:
  CustomerArrived(c)  CustomerAtShelf(c)  CustomerQueued(c, index)  QueueChanged
  CustomerPaid(c, coins)  CustomerLeft(c)          // Angry면 화난 퇴장
  StockChanged(breadId)  OvenChanged(index)  UpgradesChanged

Game   GameManager.Init: Shop = new ShopSim(State, Tables, new SystemRandom()). Update 틱에 Shop.Tick
World  ShopView(프리팹): 진열대 3·오븐 3·계산대·줄 칸·문 Transform, 재고 숫자·굽기 막대
       CustomerSpawner: 이벤트 → Customer 개체(Visitor 개명) 생성·이동·파괴
       Customer: Unit. Phase 이벤트마다 WalkState(목표 칸, 도착 시간) · 말풍선(원하는 빵 / 화남)
       Wombat: 계산대 뒤 고정, 계산 중 idle 모션
       오븐 탭 → WorldManager가 판정(기존 Camera_Tapped 재사용) → 이벤트 OvenTapped(index)
UI     BakePopup(View+Presenter): 해금 빵 목록·굽는 시간 → ShopSim.TryBake
       UpgradePopup(View+Presenter): 업그레이드 행 + 빵 해금 행, 비용·단계 → TryUpgrade/TryUnlock
       ShopHud: 기존 + 업그레이드 버튼
```

- World의 오븐 탭은 UI 팝업을 직접 열지 않는다. `WorldManager.OvenTapped` 이벤트를 `MainScene`이 받아 `BakePopup`을 연다(World와 UI는 서로 모른다는 규칙 유지).
- 코인은 `ZooState.AddCoins/TrySpend` 한 곳.
- `Unit.Setup`에 좌표 변환 주입(v0.2와 같음): 지상 `Iso.ToScreen`, 가게 내부는 항등.

## 4. Data (데이터-테이블-규칙 6장: 기획서 → JSON → 검증 테스트)

| 테이블 | 내용 |
|---|---|
| `breads.json` 신규 | `id, name, sprite, bakeSeconds, batchSize, price, weight, unlockCost`. b01 식빵(8초, 6개, 10, 시작 해금) · b02 크루아상(15초, 4개, 25, 해금 500) · b03 케이크(30초, 2개, 80, 해금 3000) |
| `shop_upgrades.json` 신규 | `id, name, baseCost, costGrowth, maxLevel, effectPerLevel`. `oven_count`(1→3) · `oven_speed`(+20%/단계) · `shelf_capacity`(기본 8, +4/단계) · `checkout_speed`(+20%/단계) |
| `game_config.shop` 추가 | `arrivalSeconds` 4 · `maxCustomers` 8 · `walkSeconds` 2 · `patienceSeconds` 6 · `checkoutSeconds` 1.5 · `shelfCapacity` 8 · `ovenCount` 1 |
| `visitors` → `customers` | 개명(.meta 유지). `viewSeconds*` 열 삭제 |
| `strings` | 업그레이드·빵 이름·팝업 문구 키 |

더미 아트: 빵 3종·진열대·오븐·계산대·말풍선은 Pillow 단색 더미, 경로는 JSON 칼럼. 실제 아트는 아트-프롬프트 0장 절차로 나중에.

## 6. 남은 결정 (권장안으로 진행 가능)

1. 손님 도착률을 무엇이 올리나 — ① 08은 고정, 12에서 홍보·위치로(권장) ② 가게 수준에 따라 자동 증가.
2. 재고 넘침 — ① 버림(권장, 굽기 선택을 신중하게) ② 가득 차면 굽기 시작 불가.
3. `Visitor`→`Customer` 개명을 08에서 한다(권장).
