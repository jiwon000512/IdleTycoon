## 왜 다시 타이쿤인가

6회차(웜뱃 디펜스)에 대한 사용자 평: "참신한 아이디어도 있었지만 개발했을 때 **매출이 잘 나올지는 모르겠다.** 다시 타이쿤으로 돌아가 재미있는 기획을 뽑아 봐라. **기존 장르와 중복되어도 된다.**"

→ 이번에는 **참신함을 채점하지 않는다.** 검증된 구조를 그대로 뼈대로 써도 된다. 기준은 둘: ① 이 사람이 재미있어할 것인가(재미 프로필) ② 매출 구조가 서는가(조사 파일). 다만 "복제 게임 홍수 속에서 스토어에서 구별되는 한 가지"는 있어야 한다 — 그것은 새 장르가 아니라 **업종·세계·동물 직원의 역할·한 가지 규칙** 수준이면 충분하다.

## 고정된 틀

- **타이쿤(방치형 경영).** 사용자가 재밌게 한 모양은 **한 화면 가게 키우기**(고양이 스낵바·Eatventure류)와 **숫자가 폭발하는 방치 경영**(AdVenture Capitalist·Idle Miner류)이다. 캐릭터가 직접 뛰어다니는 아케이드 타이쿤과 내가 짓고 배치하는 건설형은 고르지 않았다 — 핵심으로 삼지 마라.
- **웜뱃이 주인공인 동물 세계.** 동물원일 필요는 없다. 업종은 자유(굴 호텔, 온천, 빵집, 야시장, 택배, 광산, 기차역, 유치원…). 제목·아이콘·얼굴은 웜뱃.
- 이 사람의 **최고의 순간**을 구조로 만들어라: ① 새 가게·새 구역이 열릴 때 ② 직원·매니저로 손을 놓게 될 때(자동화 계단) ③ 좋은 캐릭터·아이템을 뽑았을 때 ④ 막혀 있던 벽을 뚫을 때 ⑤ 새 유닛(동물)으로 확 세질 때.
- 계속 켜는 이유 = 점점 세지는 성장 + 짧게 자주 확인하는 리듬(1~3분 접속, 하루 4~6회, 방치 보상). 접는 이유 = 할 일이 똑같아짐 + 피곤·부담. 싫어하는 것 = 복잡한 메뉴·재화(재화 3종 이내, 강화 화면 여러 겹 금지).
- 운은 후보를 주고 선택은 내가(3택 1). 환생(리셋 + 배수)도, 다음 가게로 넘어가기도 둘 다 괜찮다.
- 새 동물은 숫자만 다른 직원이 아니라 **가게 운영 규칙을 바꾸는 동사**를 가져야 한다(6회차에서 통한 방식: 끌어당긴다·재운다·업는다·흉내 낸다·퍼 나른다…).
- 목표 1순위 **수익**: 보상형 광고·가차·광고 제거/월정액/패스·성장 패키지 전부 허용. 강제 전면 광고는 넣지 않는다.
- 1인 개발, Unity, 모바일 세로 한 손, 2D 픽셀아트(코지, 진갈색 외곽선), 3~6개월에 첫 버전. **이미 있는 것**: 웜뱃 스프라이트(정지·idle·걷기), 수입 틱·오프라인 수익 계산·비용 곡선·가차 확률 코드(순수 C#), JSON 데이터 테이블 파이프라인, uGUI MVP 구조, 이미지 생성 파이프라인. 쿼터뷰 동물원 맵(존 3×3·관광객·시설)도 있지만 꼭 쓸 필요는 없다.

## 출력 형식 (기획 하나당 — 게임 하나의 기획)

```
### N. 제목 (가제) — 제목만 읽어도 무슨 게임인지 보이게
- 한 문장: 친구에게 설명하는 한 문장.
- 업종·세계: 웜뱃이 무엇을 운영하는가. 손님은 누구이고 무엇을 사 가는가.
- 화면 구성: 세로 한 화면에 무엇이 어떻게 보이는가(위에서 아래로). 첫 화면이 곧 15초 광고가 되는가.
- 핵심 루프: 30초(지금 손이 하는 일) / 3분(한 번 접속) / 하루(돌아오는 이유).
- 이 게임만의 한 가지: 다른 타이쿤과 구별되는 규칙 또는 구조 하나. 숫자 예시 포함. 없어도 되는 장식이면 안 된다 — 매일의 결정을 바꿔야 한다.
- 새 그림이 열리는 속도: 새 가게·구역·층·테마가 언제 열리는가(첫 10분, 첫날, D3, D7…). 열릴 때 무엇이 새로 보이는가.
- 자동화 계단: 처음에 손으로 하던 일 → 어떤 동물 직원이 → 어떤 순서로 대신하게 되는가. 다 넘긴 뒤 손에 남는 결정은 무엇인가.
- 동물 직원 8종: 이름 · 동사(역할) · 가게 운영이 어떻게 달라지는가 한 줄씩. 새 동물이 기존 배치·전략을 뒤집는 사례 2개.
- 뽑기와 3택: 무엇을 뽑는가(직원·레시피·설비…), 3택 1이 어디에 얼마나 자주 있는가.
- 벽과 돌파: 타이쿤에서 벽은 무엇인가(손님 눈높이, 평론가, 구역 개방 조건, 경쟁 가게…). 막힌 이유가 눈에 보이는가. 뚫는 법 3가지.
- 장기 구조: 환생 / 다음 가게 / 도시 확장 중 무엇으로 D30 이후를 버티는가. 콘텐츠는 데이터 테이블로 늘어나는가.
- 단계적 개방: D1 · D3 · D7 · D14 · D30 에 열리는 것 한 줄씩. 재화 목록(3종 이내), 강화 축 수.
- 수익 설계: 보상형 광고 자리(하루 몇 회, 어디), 주력 IAP(광고 제거·직원 가차·시간 스킵·패스·성장 패키지 중 무엇이 1번인가), 첫 결제 유도 지점, 이벤트를 1인이 테이블로 돌리는 방법.
- 레퍼런스(01 조사 파일에서): 1~2개. 가져올 것(수익 구조·세션·광고 훅) 하나 · 다른 점 하나.
- 1인 개발 비용: 아트(가게 그림·설비·직원·손님 프레임 수 어림), 기술 위험, 재사용할 기존 코드, 3~6개월 첫 버전의 범위.
- 가장 큰 약점: 정직하게 한두 줄.
```
