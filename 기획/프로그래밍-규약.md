# 프로그래밍 규약

버전 v1.3 · 2026-09-24
코드를 한 줄씩 쓸 때 따르는 규칙. 구조와 설계(계층, MVP, 의존 방향)는 `코드-규칙.md`, 데이터 형식은 `데이터-테이블-규칙.md`가 정한다. 이 문서는 유니티 공식 **C# 코드 스타일 가이드(Unity 6판)** 를 기본으로 하고, 가이드가 팀 선택으로 남긴 항목만 1장에서 확정한다. 가이드에 없는 항목은 .NET 관례를 따른다.

적용 범위: 게임 코드(ZooTycoon.*), 공통 기반 패키지(GameKit.*), 테스트, 에디터 도구 전부. 사람과 AI 에이전트 모두 따른다. 위반은 리뷰에서 잡고, 도구가 잡을 수 있는 것은 `.editorconfig`에 넣는다.

## 3. 포맷

- 들여쓰기 공백 4칸. 탭 금지. 한 줄 120자. UTF-8, LF, 파일 끝 개행.
- **Allman**: 클래스·메서드·프로퍼티·제어문 모두 여는 중괄호를 새 줄에. 한 줄 본문이라도 중괄호 생략 금지.
- 공백: 제어문 키워드 뒤 한 칸 `if (x)`, 메서드 이름과 괄호 사이 없음 `Foo(x)`, 괄호 안쪽 없음, 쉼표 뒤 한 칸, 이항 연산자 양쪽 한 칸, 단항·멤버 접근 없음.
- 빈 줄: 멤버 사이 한 줄. 메서드 안에서는 논리 단위 사이 한 줄. 연속 두 줄 이상 빈 줄 금지. 파일 첫 줄은 `using`.
- 한 문장에 한 줄. 한 줄에 선언 하나(`int a, b;` ✗).
- 긴 인자 목록은 첫 인자부터 줄을 바꾸고 한 단계 들여쓴다. 메서드 체인은 `.` 앞에서 줄바꿈.
- `if-else if`가 세 갈래를 넘으면 `switch`. `switch` 식(expression)은 값 매핑에 허용.
- 표현식 본문(`=>`)은 한 줄로 끝나는 getter·단순 반환에만. 로직이 있으면 블록.
- `var`는 우변에서 타입이 보일 때(`new`, 캐스트, `foreach`)만. 메서드 반환값을 받을 때는 타입을 쓴다.
- 문자열은 보간(`$"..."`). 연결 `+`는 상수 결합에만. 숫자 리터럴은 `1_000_000`처럼 자릿수 구분.
- 속성(attribute)은 대상 위 줄에 하나씩. `[SerializeField] private int m_x;`처럼 한 줄에 붙이는 것은 필드에만 허용.

## 4. 파일과 클래스 구성

- `using`은 파일 맨 위. 순서: `System*` → `UnityEngine*`/`UnityEditor*` → 서드파티 → 프로젝트(`GameKit.*`, `ZooTycoon.*`). 그룹 사이 빈 줄 없음, 알파벳 순. 미사용 `using` 제거. `using static`은 쓰지 않는다.
- 네임스페이스는 블록 형식(`namespace X { }`). 파일 범위 네임스페이스(C# 10)는 Unity 6에서 불가.
- 파일당 최상위 타입 하나. 그 타입만 쓰는 작은 보조 타입(결과 구조체, private 중첩 클래스, enum)은 같은 파일에 둘 수 있다. MonoBehaviour는 파일당 하나, 파일명 일치.
- 멤버 순서(가이드): ① 상수·static 필드 ② `[SerializeField]` 필드 ③ 그 외 필드 ④ 프로퍼티 ⑤ 이벤트 ⑥ 생성자 ⑦ Unity 이벤트 함수(Awake → OnEnable → Start → Update → OnDisable → OnDestroy 순) ⑧ public 메서드 ⑨ 이벤트 발생 `On...` 메서드 ⑩ 핸들러 `Subject_Event` ⑪ private 메서드 ⑫ 중첩 타입.
- 접근 제한자는 항상 쓴다(`private` 포함). 다른 어셈블리가 쓰지 않으면 `internal`이 아니라 `public`을 남기지 않는다: 기본은 `private` → 필요할 때 `internal` → 패키지 밖에서 쓸 때만 `public`.
- 클래스 200줄, 메서드 40줄, 매개변수 5개를 넘으면 분리를 검토한다(`코드-규칙.md` 7장).
- `#region` 금지. 주석 처리된 코드 금지.

| 기능 | 규칙 |

| 튜플 | private/internal 반환에만. public API는 이름 있는 결과 타입 |

| `dynamic`, `goto`, `unsafe`, `partial`(생성 코드 제외) | 금지 |
| `static` 클래스 | 순수 함수 모음(`BigNumberFormatter`, `…Extensions`)에만. 상태를 갖는 static 금지 |

## 6. 오류 처리

- **예상된 실패**(정상 흐름에서 일어날 수 있음)는 값으로 돌려준다. 코인 부족, 세이브 없음, 테이블 검증 실패, 잠긴 우리.
  - 값이 없는 성공/실패: `Result` (`IsSuccess`, `Error`).
  - 값이 있는: `Result<T>` (`Value`, `Error`). `Error`는 `ErrorCode`(enum) + 메시지.
  - 단순 조회는 `bool TryGetXxx(key, out value)`.
- **프로그램 오류**(호출자 버그)는 예외. 잘못된 인자 `ArgumentException`계열, 잘못된 상태 `InvalidOperationException`, 초기화 전 사용 `InvalidOperationException`. 메시지는 한국어로 원인과 조치를 적는다.
- `catch`는 경계에서만: 파일 IO, JSON 파싱, 네트워크, 서드파티 SDK. 잡은 뒤 `Result` 실패로 바꾼다. 빈 `catch`, `catch (Exception)`으로 삼키기 금지.
- **로그는 최소한으로.** 실패 경계(IO·파싱·네트워크)와 초기화 실패에만 남긴다. 정상 흐름·상태 추적 로그는 넣지 않는다.
- 예외를 흐름 제어로 쓰지 않는다(`try`로 존재 확인 ✗).
- Unity 콜백(Update 등) 안에서 예외가 나면 프레임이 끊기므로, 콜백은 서비스 호출만 하고 서비스가 `Result`를 돌려준다.
- 단언(assert): Core 내부 불변식은 `Debug.Assert` 대신 예외로 표현한다(릴리스에서도 유효).

## 7. 이벤트

- 델리게이트는 `System.Action`/`Action<T>`. `EventHandler`·커스텀 델리게이트는 쓰지 않는다.
- 선언: `public event Action<int> CoinsChanged;`. 매개변수 3개를 넘으면 불변 인자 타입 하나로 묶는다.
- 발생은 소유 클래스 안에서만, `private void OnCoinsChanged(int coins) => CoinsChanged?.Invoke(coins);`
- 구독은 반드시 쌍으로 해제: MonoBehaviour는 `OnEnable`/`OnDisable`, 순수 C#은 `IDisposable.Dispose`. 익명 람다 구독은 해제할 수 없으므로 금지(EventManager 토큰 반환 방식은 예외).
- EventManager(Game·UI 계층 전역 알림)와 C# event(소유자→직접 구독자)의 구분: 직접 참조 관계면 C# event, 발행자와 구독자가 서로 몰라야 하거나 구독자가 여럿이면 EventManager. Core 계층은 EventManager를 쓸 수 없으므로 C# event만 쓴다.
- 이벤트는 타입으로 식별한다(enum 키·문자열 키 금지). 페이로드가 곧 타입이라 캐스트가 없다. 도메인 구분은 폴더·네임스페이스로 하고, 수명이 짧은 도메인이 생기면 전역 대신 그 도메인이 소유하는 인스턴스를 둔다.
- 이벤트 안에서 다시 같은 이벤트를 발생시키지 않는다(재진입 금지).

## 8. 주석과 문서

- 주석·문서·커밋 메시지는 한국어. 식별자는 영어.
- **주석은 최소한으로.** 이름과 구조로 의도를 드러내고, 주석은 규칙 예외·기획서 표 번호·비자명한 "왜"에만 쓴다. 코드가 무엇을 하는지 설명하는 주석은 이름을 고쳐 없앤다.
- `///` 요약은 패키지 밖에서 쓰는 public 타입에 한 줄 정도. 메서드마다 붙이지 않는다. `<param>`은 쓰지 않는다.
- 직렬화 필드는 `[Tooltip("...")]`으로 인스펙터 설명. 주석 대신.
- 기획서 숫자를 다루는 코드는 표 번호를 적는다: `// 기획서 6.3: 비용 = base × growth^n`.
- `// TODO(이름): 내용 — 기한/조건`. 조건 없는 TODO 금지.
- 규칙을 어길 때: `// 규칙 예외: <이유>` (`코드-규칙.md` 6장).

## 9. Unity 특화

- `Awake`: 자기 컴포넌트 캐시·`[SerializeField]` 검증. `Start`: 다른 객체에 의존하는 초기화. `OnEnable`/`OnDisable`: 구독·해제. `OnDestroy`: 코루틴·핸들 정리.
- `GetComponent`는 `Awake`에서 한 번 캐시. `Update`·코루틴 안에서 호출 금지.
- `Update`에는 게임 규칙을 두지 않는다(`코드-규칙.md`). 표시 보간·입력 폴링만.
- `[RequireComponent]`로 필수 컴포넌트를 선언한다. `[SerializeField]`가 비어 있으면 `Awake`에서 명확한 예외를 던진다.
- 태그·레이어·Resources 경로·애니메이터 파라미터 같은 문자열은 `k_` 상수로 한 곳에. 리터럴 산재 금지.
- 코루틴은 연출에만. 시작 핸들을 필드에 보관하고 `OnDisable`에서 `StopCoroutine`.
- `Find`, `FindObjectOfType`, `SendMessage`, `Invoke("문자열")` 금지.
- 프리팹·씬의 인스펙터 참조는 `[SerializeField] private` + 프로퍼티. 런타임 생성 객체 참조는 코드로 주입.
- 저장: 게임 상태(세이브)는 GameKit `DataManager`(JSON 파일, 원자적 교체). 기기 설정(볼륨·언어 같은 값 한두 개)만 `PlayerPrefs`.

## 10. GameKit Manager 규약

- 모든 Manager는 `MonoSingleton<T>`를 상속한다. `T.Instance` 첫 접근 시 `GameObject`를 만들어 `DontDestroyOnLoad`로 붙이고, 씬에 미리 놓인 인스턴스가 있으면 그것을 쓴다. 두 번째 인스턴스는 스스로 파괴한다. 베이스는 이 셋(생성·중복 파괴·유지)만 한다.
- 자기 초기화: 파생 클래스는 `Awake`(base.Awake 호출 후)에서 기본 설정으로 동작 가능한 상태가 된다. 별도 `Initialize` 호출 없이 바로 쓸 수 있는 것이 계약이다.
- 기본 구현(예: `Resources` 테이블 소스, 파일 저장소)을 바꿔야 하면 그 Manager에 `Configure(...)`를 두고 부트스트랩 시작 지점에서 호출한다. 호출 순서 가드는 두지 않는다.
- 호출자는 `OnDestroy`·종료 중에 Manager를 쓰지 않는다. 베이스는 종료를 감지하지 않는다.
- 접근 허용 범위: `Game`·`UI` 계층과 GameKit 내부. `Core`·`Data`는 어셈블리 경계로 접근이 불가능하며, 게임 규칙 서비스는 Manager를 직접 참조하지 않고 필요한 인터페이스(`ISaveStorage`, `ITableSource`)를 생성자로 받는다. Manager는 그 인터페이스 구현을 제공하는 파사드다.
- Manager에 게임 규칙을 넣지 않는다. 로직이 순수 C#로 분리될 가치가 있으면(테이블·저장·스케줄러) Core 클래스를 감싸고, 그렇지 않으면(EventManager) Manager 안에 직접 둔다. 테스트는 분리된 순수 클래스로 한다.
- 이름은 `역할 + Manager`: `UIManager`, `TableManager`, `DataManager`, `EventManager`, `PoolManager`. 이 접미어는 GameKit 파사드 전용이다.

## 11. 테스트

- EditMode 테스트, NUnit. 파일 `대상Tests.cs`, 메서드 `대상_조건_기대`.
- 본문은 준비 / 실행 / 검증을 빈 줄로 나눈다. 테스트 하나에 검증 대상 하나.
- 결정적이어야 한다: `IClock`·`IRandom`은 테스트 대역(`FixedClock`, `SequenceRandom`)을 쓴다. 실제 시간·난수·파일 시스템 금지.
- 기획서 표의 숫자를 그대로 케이스로 옮기고 표 번호를 테스트 이름이나 주석에 남긴다.
- 실패 메시지는 기대와 실제를 드러내는 `Assert.That(actual, Is.EqualTo(expected))` 형태.
