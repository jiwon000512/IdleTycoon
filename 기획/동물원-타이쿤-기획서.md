## 1. 개요

- 1인 개발 모바일 게임. AI(이미지 생성·코딩 보조)를 활용해 만들고 출시해 수익화한다.
- 장르: **방치형 경영 타이쿤**. 방치형 요소를 타이쿤보다 강하게, 캐주얼하게. 지속형(리셋 없음).
- 한 줄: 코인으로 존(우리)을 열고 어떤 동물을 들일지 골라 입주시키면, 시간이 지나며 번식해 늘어나고 관광객 수입(초당)이 커진다. 코인은 다음 존·종·의상·시설에 쓴다.
- 레퍼런스 구조: 고양이 오피스(방을 열고 → 회사와 계약하면 → 직원이 들어와 일한다). 우리 게임은 방 = 존, 계약 = 종 선택 입주, 직원 = 동물. 차별점은 **살아있음**(번식으로 늘어남)과 **애착**(종 단위 의상) (v0.17).
- 개발 순서: 메인 루프를 먼저 만들고, 루프가 재미있다고 확인된 뒤 컨텐츠를 붙인다.
- 아트: 귀여운 SD 2D. ChatGPT 이미지 생성 → 배경 제거 → 스프라이트 애니메이션.

## 3. 핵심 루프

재화는 코인 하나, 소비처는 존 개장·종 입주·의상·시설 넷, 성장 축은 마리(시간)·존과 종(코인)·배수(코인) 셋 (v0.17).

1. **존을 연다** — 잠긴 존을 탭해 개장 비용을 내면 빈 존이 된다(첫 존은 처음부터 열려 있다).
2. **종을 고른다(계약)** — 빈 존을 탭하면 입주 가능한 종 목록. 입주비를 내면 그 종 1마리가 존에 나타나 돌아다닌다.
3. **번식** — 종의 번식 주기마다 한 마리가 늘어난다. 존의 최대 마리 수에서 멈춘다. 새로 태어난 마리는 존 안에 개체로 하나 더 보인다.
4. 존마다 **초당 수입** = 종 수입 × 마리 수 보정(6.2) × 의상 배수 × 시설 배수. 전체 합이 코인으로 쌓인다.
5. 코인은 **다음 존 개장·새 종 입주·의상·시설**에 쓴다. 누적 획득 코인이 동물원 레벨을 올리고, 레벨이 존·종·시설·의상을 해금한다.
6. 앱을 닫아둔 동안은 초당 수입 × 경과 시간(캡)을 복귀 시 **오프라인 수익**으로 지급하고, 번식도 경과 시간만큼 진행한다.

이 게임의 결정은 "지금 코인을 새 존·종(수입 원천)에 넣을까, 의상·시설(배수)에 넣을까"이고, 복귀 동기는 "돌아오면 늘어나 있다"이다. 존 한도가 마리 수를 멈춰 세우므로 세션마다 "찼다 → 다음 존" 리듬이 생기게 존 개장 비용과 번식 주기를 맞춘다.

## 4. 화면 구성

세로 고정, 기준 해상도 1080×1920. 화면은 **2D 월드 맵**(스프라이트) 위에 **HUD**(uGUI 오버레이)를 얹은 구조다 (v0.9).

**월드**

| 요소 | 내용 |
|---|---|
| 존 | 맵 위의 울타리 친 구역이 세로로 여러 개(첫 버전 3자리). 크기·위치·최대 마리 수는 `zones.json`. 잠긴 존은 자물쇠와 개장 비용 표시, 빈 존은 "입주" 표시. 한 존에 한 종만 산다 (v0.17) |
| 시설 | 존 안 네 모서리의 정해진 자리에 놓이는 스프라이트. 1단계를 사면 나타난다. 자리·해금 레벨·단계·배수·비용은 `facilities.json` (v0.16) |
| 동물 | SD 스프라이트가 존 안을 자유롭게 돌아다닌다(목적지로 걷기 → 멈춤 → 다시 걷기). 번식으로 늘어난 마리는 개체로 하나씩 더 보인다. 의상은 개체 위에 같은 프레임의 두 번째 레이어 (v0.17) |
| 관광객 | 존마다 앞(카메라 쪽)에 길 띠가 한 줄 있고, 실루엣이 한쪽 끝에서 나타나 가로질러 반대쪽으로 나간다. 동물이 있는 존 앞에서 멈춰 구경하면 머리 위에 코인이 떠올라 사라진다(연출). 수는 초당 수입에 따라 는다(v0.14) |
| 카메라 | 사방으로 자유 팬(드래그). 팬 범위는 존 3자리 + 길 + 여유 |
| 시점 | 순수 2D 쿼터뷰(v0.19). 존은 화면에서 마름모(바닥 스프라이트 1장), 울타리는 칸 스프라이트를 네 변에 늘어놓음(왼쪽·오른쪽 변은 좌우 반전), 앞길은 대각선 평행사변형. 동물·관광객은 정면 카드 + 타원 그림자. 정렬은 화면 y(정렬점 = 발끝·기둥 밑). 픽셀 퍼펙트는 이후 |

**HUD와 팝업**

| 영역 | 내용 |
|---|---|
| 상단 바 | 코인(K/M/B 표기) · 초당 수입(`초당 n`) · 동물원 레벨(`Lv.n`)과 진행도(`누적/다음 기준`, 마지막 레벨이면 `MAX`) |
| 존 팝업(존 탭) | 잠긴 존: 이름·최대 마리 수·개장 비용·`Lv.n 해금`. 빈 존: 입주 가능한 종 목록(이름·실루엣·초당 수입·입주비·`Lv.n 해금`). 찬 존: 종 이름·마리 수/최대·다음 번식까지 남은 초 (v0.17) |
| 꾸미기 버튼 → 팝업 | 카메라가 보고 있는 존의 것. 탭 2개: 시설(07 그대로) · 의상(부위별 목록: 이름·효과 ×배수·비용, 보유는 `착용`/`착용 중`) (v0.17) |
| 도감 팝업 | 종 목록: 입주 여부·마리 수·보유 의상 |
| 오프라인 팝업 | 복귀 시 수익과 번식으로 늘어난 마리 수 표시(광고 2배 자리는 비워 둠) |

첫 버전에서 플레이어가 하는 것은 존 탭(개장·입주), 꾸미기 버튼(시설·의상), 화면 드래그 세 가지다.

## 6. 데이터와 숫자 초안 (전부 시작값, 프로토타입에서 튜닝)

### 6.1 동물 (animals.json, v0.17)

실제 아트가 준비된 종부터 한 종씩 넣는다. 등급·뽑기 가중치·`variantId`는 삭제하고 입주비·번식 주기·해금 레벨을 둔다.

| ID | 이름 | 기본 초당 수입 | 입주비 | 번식 주기 | 해금 | 연출값(시작값) |
|---|---|---:|---:|---:|---|---|
| a01 | 웜뱃 | 1.0 | 100 | 60초 | Lv.1 | idle·move 6프레임 8fps, 크기 1.0, 이동 1.2유닛/초, 대기 1~3초 |

### 6.2 마리 수와 수입

- 마리 수: 입주 1마리에서 시작, 번식으로 +1, 존의 최대 마리 수까지. 코드·데이터 이름은 `Count`
- 종의 초당 수입 = 기본 × (1 + 0.5 × (마리 수 − 1)). 8마리 = 4.5배, 15마리 = 8배, 25마리 = 13배
- 존 수입 = 종 수입 × 의상 배수(부위별 곱) × 시설 배수(07). 총 수입 = Σ 존 수입

### 6.3 존 · 입주 · 번식 리듬 (zones.json)

| ID | 위치 | 최대 마리 | 해금 | 개장 비용 | 의도 |
|---|---|---:|---|---:|---|
| z01 | 가운데 | 8 | Lv.1 | 0(열림) | 웜뱃 입주 후 약 7분에 가득(60초 × 7). 가득 찬 뒤 수입 4.5/초 |
| z02 | 뒤 | 15 | Lv.3 | 3,000 | 두 번째 종의 자리. Lv.3(누적 8,000)과 비용이 같은 시기에 맞도록 |
| z03 | 앞 | 25 | Lv.5 | 20,000 | 세 번째 종 |

존 크기(이동 영역·타일 수)는 행에 두되 첫 버전은 셋 다 03의 우리 크기(9.6 × 12.2유닛). 아트가 오면 존별로 바꾼다.
목표 리듬: 첫 세션 5분 동안 입주 1회 + 새끼 4~5마리 + 의상 1개. 이후 접속당 "찼는지 확인 → 코인 쓸 곳 하나". 종이 하나뿐인 동안 z02·z03은 열어도 입주할 종이 없으므로 리듬 검증은 웜뱃 존 하나로 한다.

### 6.4 의상 · 시설 · 동물원 레벨 · 오프라인 · 시작 상태

- 의상(`costumes.json`, v0.17): 종별·부위별 행. 부위는 `hat`·`cloth`. 배수는 그 종 수입에 곱, 부위끼리 곱. 웜뱃 더미: 밀짚모자 300코인 ×1.2 Lv.1 · 멜빵바지 1,000코인 ×1.3 Lv.2. 한 부위에 하나만 착용, 산 것은 도감에 남는다
- 시설(`facilities.json`, v0.16): 존마다 네 모서리 + 단계. 총 배수 = Π(1 + 단계당 배수 × 단계), 비용 = base × growth^단계. 값은 v0.16 그대로(홍보 Lv.3 10단계 +10% 500 × 1.8^k · 벤치 Lv.2 · 매점 Lv.4 · 나무 Lv.5). 단계는 존별로 저장
- 관광객 수(v0.14, `game_config.visitors`): 초당 수입이 0이면 0명, 그 외 min(12, 1 + ⌊log₂(1 + 수입 ÷ 1)⌋). 존마다 그 존 수입으로 계산
- 동물원 레벨(누적 획득 코인): Lv.1 0 · Lv.2 2,000 · Lv.3 8,000 · Lv.4 25,000 · Lv.5 70,000 · Lv.6 200,000 · Lv.7 500,000. 해금 레벨은 각 테이블(`zones`·`animals`·`facilities`·`costumes`)의 `unlockLevel`에 있고 `zoo_levels`에는 기준 코인만
- 오프라인: 복귀 시 초당 수입 × 경과 초(최대 8시간). 번식은 존마다 ⌊경과 ÷ 주기⌋마리를 한도까지 더한다(수입은 복귀 시점 마리 수가 아니라 떠날 때 마리 수 기준, 단순화)
- 시작 상태: 코인 350, z01 열림(빈 존), z02·z03 잠김, 동물 0, 의상·시설 0. 첫 행동은 z01 탭 → 웜뱃 입주(100). 이것이 튜토리얼을 대신한다

## 7. 한 세션의 흐름 ("하루 몇 번 들여다보기", 1~3분)

1. 앱을 연다 → 오프라인 수익과 "웜뱃이 n마리 늘었어요" 팝업을 받는다.
2. 존을 보며 마리가 늘었는지 확인한다. 가득 찼으면 다음 존·종을 살 수 있는지 본다.
3. 코인이 있으면 의상이나 시설을 하나 산다. 의상은 존의 동물 전체가 바로 갈아입는다.
4. 동물원 레벨이 올랐으면 새 존·종·의상·시설이 열린다.
5. 도감을 한 번 열어보고 나간다. 복귀 동기는 "얼마나 늘었을까"와 "다음 존을 열 수 있을까".

첫 버전에서 확인할 질문: 웜뱃 존이 가득 찬 뒤(약 7분)에도 다음 접속이 기다려지는가. 아니라면 번식 주기·존 한도·의상 효과를 바꾸고, 그래도 아니라면 새끼 성장 연출·동물 터치를 앞당긴다.

## 8. 구현 메모 (제안)

- 데이터: JSON 테이블 8개(`Assets/Resources/Data/`) — animals(id, 이름, 기본 수입, 입주비, 번식 주기, 해금 레벨, 연출값), zones(id, 이름, 위치·크기, 최대 마리, 개장 비용, 해금 레벨), costumes(id, 종, 부위, 이름, 시트, 배수, 비용, 해금 레벨), zoo_levels(레벨, 누적 코인 기준), facilities(v0.16), visitors(관광객 종류), game_config(시작 상태, 마리 수 보정, 오프라인 캡, 틱), strings(UI 문구). `grades.json`은 삭제. JSON이 유일한 원본이고 Newtonsoft.Json으로 로드, 스프라이트는 경로 칼럼으로 참조, EditMode 테스트로 검증. 형식은 `데이터-테이블-규칙.md`
- 세이브: JSON 1파일 — 코인, 누적 코인, 존 배열(존 id, 열림, 종 id, 마리 수, 번식 진행 초, 시설별 단계, 부위별 의상 id), 마지막 저장 시각(UTC). 복귀 시 (now − lastSaved)를 8시간으로 잘라 초당 수입을 곱하고 존마다 번식을 진행
- 숫자: double + K/M/B 표기 함수. 수입 갱신은 1초 틱(v0.10), 번식 타이머도 같은 틱에서 진행
- 월드: 순수 2D(v0.19). 존은 논리 사각형 3개(바닥·이동 영역·앞길)와 스프라이트 3장(바닥·길·울타리 칸)을 가진 컴포넌트이고 바닥·길·울타리를 `Awake`에서 세운다. 개체는 논리 위치(XZ)로 움직이고 `Iso.ToScreen`으로 화면에 놓인다. 의상은 개체의 `ModelRoot` 아래 두 번째 SpriteRenderer, `SpriteAnimator`가 같은 프레임 번호로 갱신. 시설은 존의 자식(v0.16). 카메라는 2D 드래그 팬 + 화면 경계 클램프
- 존 탭: 월드 카메라에서 레이캐스트 대신 존 앞의 uGUI 버튼 없이, `WorldView`가 탭 위치를 XZ 평면에 투영해 존 Rect를 찾는다(설계 08에서 확정)
- 아트 파이프라인: 이미지 생성 → 배경 제거 → 대기·걷기 시트 → 의상은 같은 프레임 수의 시트를 종별로. 눕는 것(바닥·길·잔디)은 위에서 본 seamless 텍스처로 생성하면 에이전트가 2:1 평행사변형으로 변환, 서 있는 것(울타리 칸·시설·자물쇠)은 쿼터뷰 3/4 각도로 생성. 프롬프트는 `기획/아트-프롬프트.md` 월드 절(v0.19)

## 9. 루프 다음에 붙일 것 (우선순위, v0.17)

로드맵 08~11(존·입주·번식, 의상, 저장·오프라인, 도감)이 끝난 뒤의 순서. 시작값이며 "존이 가득 찬 뒤" 답을 보고 조정한다.

1. 새끼 성장(9.1 A2) — 작게 태어나 자라는 스케일. 번식의 시각적 보상
2. 동물 터치(B1)와 미션 — 지켜보는 동안의 조작과 짧은 목표
3. 리워드 광고 — 오프라인 수익 2배, 번식 즉시 1회, 수입 부스트 (첫 수익원)
4. 마일스톤 배수(C10) — 종의 마리 수 문턱에서 그 종 ×2(존 한도 안에서 5·10·20)
5. 종 추가 — 실제 아트 순. 종이 늘어야 z02·z03이 의미를 가진다
6. 의상 실제 아트 + 스킨 IAP
7. 시설 확장(C3) — 관광객 수 × 단가 유형, 단계별 아트
8. 2호점(C1) — 지점 유지형. 저장 모델은 처음부터 지점 배열
9. 이벤트 존(C9) — 기간 한정 종·별도 존을 데이터 템플릿으로
10. 튜토리얼·사운드·BGM, 업적, IAP(광고 제거)

후순위 옵션(필요가 확인될 때만): 계약 변경(존 비우기), 개체 단위 의상, 번식 속도 업그레이드, 지점 단위 선택 환생(C11), 머지(D1).

### 9.1 재미 요소 후보 (2026-09-14 기록, v0.17에서 정리)

뽑기 순간을 살리는 A1(색깔 변형)·A3(행운 게이지)은 뽑기 폐기로 함께 폐기. A2(개체 크기·새끼 성장)는 9장 1번으로 채택. B(동물 터치·바닥 코인·부스트)와 C(후반 곡선)는 유지하며 내용은 v0.16 기획서(git 이력)와 같다. D(공장식 프레임)는 v0.13 결정대로 전환하지 않는다.

**존·계약 구조 결정 근거(2026-09-15)**: 고양이 오피스의 "방 → 회사 계약 → 직원" 구조를 대응하면 존 → 입주 → 동물이 된다. 후보였던 "존마다 분류 고정 + 존별 뽑기"(C2 테마 구역)와 "테마 세트 계약 + 뽑기"(G2)는 오피스와 구조가 같아 차별점이 약했고, 뽑기의 랜덤 불만도 남았다. 채택한 H(존당 1종 입주 + 번식 + 종 단위 의상)는 뽑기를 버리는 대신 "살아있음"과 "애착"을 얻고, 웜뱃 1종으로도 번식·의상까지 검증할 수 있다. 위험은 의상 아트(종 × 아이템 × 프레임)와 코인 소비처 부족이며, 후자는 존 한도(고정)가 "다음 존·종"을 사게 만들어 막는다.
